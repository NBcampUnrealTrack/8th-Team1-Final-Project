# X-7 반복 퀘스트 배치 가이드

## 목적

X-7 반복 퀘스트 8종의 레벨 배치 기준을 한 문서에서 확인하기 위한 가이드다.

이 문서는 **맵에 무엇을 어디에 놓아야 하는지**를 다룬다.  
보상·대사·실패 수치는 `05 X-7 반복 퀘스트 기획.md`를 기준으로 한다.

> **Git 규칙:** 이 가이드를 따라 실제 맵을 수정하더라도 `Content/Maps/L_Ocean.umap`은 별도 요청이 없으면 커밋하지 않는다.

---

## 1. 현재 사용 중인 반복 퀘스트

현재 활성 반복 풀은 아래 8종이다.

| ID | 이름 | 구역 | 유형 |
|---|---|---|---|
| X7-R09 | 진입구 안전화 | 01 진입구 + 진입 항로 | 복합 |
| X7-R10 | 생물 실험실 회수 | B1-02 생물 실험실 | B급 샘플 회수 |
| X7-R11 | 데이터 코어 회수 | B1-01 유전자 분석실 | A급 샘플 회수 |
| X7-R02 | 표본 보관실 잔여 표본 수집 | 07 표본 보관실 | 손상 허용 회수 |
| X7-R05 | 냉각 시스템실 진입로 확보 | B1-05 부속 구획 | 철거 + 마감 |

---

## 2. 현재 데이터 에셋 상태 주의

2026-09-28 실측 기준으로 Repeat 데이터 에셋은 아직 일부가 기획과 맞지 않는다.

현재 확인된 공통 문제:

- 대부분의 `SpawnZoneTag`가 아직 `Env.Zone.Mothership`로 남아 있다.
- R05 / R06 / R07처럼 회수 퀘스트가 아닌 항목도 현재 데이터에서는 임시 `RECOVER_INTACT`로 남아 있다.
- R10 HUD에는 구 위치명 `04·05·06 생물실험동`이 남아 있다.
- R11 HUD에는 구 위치명 `B1 심층`이 남아 있다.
- R02 HUD에는 구 명칭 `07 저장고`가 남아 있다.

따라서 **레벨 배치는 아래 최신 기획 위치를 기준으로 진행하되, 데이터 에셋의 목표 타입과 Zone Tag가 정리되기 전에는 최종 기능 검증으로 보지 않는다.**

특히 `Env.Zone.Mothership` 그대로 `BP_QuestSampleSpawner`를 배치하면 서로 다른 방의 스포너가 같은 후보 풀에 섞일 수 있으므로 그대로 사용하지 않는다.

## 3. 공통 샘플 스포너 배치 규칙

샘플 회수형 반복 퀘스트는 기본적으로 아래 액터를 사용한다.

`/Game/Blueprint/Sample/BP_QuestSampleSpawner`

### 기본 원칙

1. 샘플을 레벨에 직접 상시 배치하지 않는다.
2. 레벨에는 **스폰 지점만** 둔다.
3. 퀘스트가 Accepted 상태가 되면 필요한 수량만 생성한다.
4. `SpawnZoneTag`는 해당 퀘스트 데이터의 `SpawnZoneTag`와 정확히 같아야 한다.
5. 같은 Zone에 스포너를 여러 개 놓으면 매니저가 그중 **대표 스포너 1개를 선택**할 수 있다.
6. 따라서 2개짜리 목표는 스포너 두 개보다 **스포너 1개 + Arrow Spawn Point 2개** 구성을 권장한다.
7. `SamplesToSpawn`은 퀘스트 `RequiredCount`와 동일하게 맞춘다.
8. 샘플이 선반·캐비닛·벽 내부에 박히지 않게 Arrow를 실제 생성 위치에 둔다.
9. Actor Label은 Outliner 정리용 이름일 뿐 필수 로직이 아니다.

### 2개 샘플 배치 예

- `BP_QuestSampleSpawner` 1개
- `SamplesToSpawn = 2`
- Arrow 2개
  - SpawnPoint_01
  - SpawnPoint_02

Arrow가 1개뿐이면 2개가 같은 위치에 겹쳐 생성될 수 있으므로 피한다.

# 5. X7-R09 — 진입구 안전화

## 배치 위치

- 외부: 모선 ↔ 01 진입구 사이 진입 항로
- 내부: 01 진입구

## 필요한 배치물

### 외부

- 부유물 2개
- 진입 동선을 방해하지 않되 플레이어가 처음 수영 구간에서 자연스럽게 발견하게 배치

### 내부

- 청소 가능 섹터
- `BP_MD_SectorCloseoutMarker`
- C급 샘플 스포너 1개

## 실제 사용하는 BP / DA

| 용도 | 실제 에셋 | 비고 |
|---|---|---|
| 퀘스트 데이터 | `/Game/Data/Quest/X7/Repeat/X7_R09` | 현재 Phase 0/1 모두 존재 |
| 진입구 섹터 | `/Game/Blueprint/Sector/BP_MDSector` | 01 진입구를 덮는 섹터 볼륨 |
| 마감 제출 | `/Game/Blueprint/Interaction/BP_MD_SectorCloseoutMarker` | `Target Sector`에 위 BP_MDSector 인스턴스 지정 |
| C급 샘플 스폰 | `/Game/Blueprint/Sample/BP_QuestSampleSpawner` | 샘플 클래스 기본값은 `BP_SampleBase` |
| 외부 부유물 배치 후보 | `/Game/Blueprint/Resource/Trash/BP_TrashSpawnVolume` | 현재 R09 전용 진행 귀속은 아직 없음 |

### X7_R09 현재 데이터 실측값

| Phase | 현재 Objective | Required Count | 현재 Zone | 등급 | HUD |
|---|---|---:|---|---|---|
| 0 | `RecoverIntact` | 1 | `Env.Zone.Mothership` | C | `01 진입구 섹터를 청소하고 절단면 마감` |
| 1 | `RecoverIntact` | 1 | `Env.Zone.Mothership` | C | `01 진입구에서 C급 연구 샘플 1개를 Intact로 회수` |

Phase 0은 기획상 **청소 + 마감**이므로 현재 `RecoverIntact`는 임시값이다. Phase 1만 실제 샘플 회수 페이즈로 사용해야 한다.

### BP_MDSector 인스턴스 세팅

| Details 항목 | 값 |
|---|---|
| BP | `BP_MDSector` |
| Sector Name | 고유 이름 지정. 권장 예: `X7_Entrance_01` |
| Volume | 01 진입구 방 내부를 덮도록 직접 크기 조정 |
| Debris Count | 기본값 `30` 유지 |
| Collapse Damage | 기본값 `40` 유지 |
| Debris Scale Min / Max | `0.2 / 0.8` 유지 |

`Volume`의 수치는 방 실제 크기에 따라 달라지므로 고정 숫자를 쓰지 않는다. 복도나 외부 항로까지 같이 잡히지 않게 01 진입구 내부만 덮는다.

### BP_MD_SectorCloseoutMarker 인스턴스 세팅

| Details 항목 | 값 |
|---|---|
| BP | `BP_MD_SectorCloseoutMarker` |
| Target Sector | 위에서 배치한 01 진입구 `BP_MDSector` 인스턴스 |
| 기본 Target Sector | `None`이므로 반드시 직접 연결 |
| 배치 위치 | 청소 후 플레이어가 확인하기 쉬운 출구 또는 작업 완료 동선 |

현재 코드에서는 마커 상호작용 시 바로 마감 점수 이벤트를 넣고, 실제 잔해/청소 조건 검사는 후속 구현 상태다. 따라서 R09 완료 조건과 연결되기 전에는 단순 점수 마커로 동작할 수 있다.

### 외부 부유물 2개 배치값

현재 R09 전용 부유물 BP는 없다. 위치 프로토타입에는 `BP_TrashSpawnVolume`을 사용할 수 있다.

| Details 항목 | R09 권장값 |
|---|---|
| BP | `BP_TrashSpawnVolume` |
| Spawn Count | `2` |
| Spawn Shape | `Box` |
| Spawn On Begin Play | `true` |
| Minimum Spacing | `75 cm` 이상 |
| Randomize Seed Each Spawn | `false` |
| Spawn Seed | 기본 `1337` 유지 가능 |
| Spawn Volume 크기 | 진입 항로에서 2개가 서로 떨어져 보이는 범위로 직접 조정 |

단, 이 BP로 생성한 쓰레기가 **R09 퀘스트 진행도에 자동 귀속되는 것은 아니다.** R09 전용 부유물 2개 카운트 연결이 구현되기 전에는 배치/동선 확인용으로만 사용한다.

## 샘플 스포너 설정

| Details 항목 | 공용 BP 기본값 | R09 배치값 |
|---|---:|---:|
| BP | `BP_QuestSampleSpawner` | 그대로 사용 |
| Sample Class | `BP_SampleBase` | 유지 |
| Samples To Spawn | `1` | `1` 유지 |
| Spawn Zone Tag | `None` | **`Env.Zone.X7.Repeat.R09`** |
| Occupied Check Radius | `80 cm` | `80 cm` 유지 |
| Spawn Protection Duration | `3.0 s` | `3.0 s` 유지 |
| Spawn Point | `DefaultSpawnPoint` 1개 | 01 진입구 선반/작업대 위치 |
| 실제 생성 등급 | BP 기본값 C | `X7_R09` Phase 1의 Accepted Grade에 의해 **C** |

현재 `Env.Zone.X7.Repeat.R09` 태그는 아직 `DefaultGameplayTags.ini`에 등록되어 있지 않다. 실제 적용 전 태그 등록과 `X7_R09` Phase 1의 `SpawnZoneTag` 수정이 필요하다.

샘플은 입구에서 바로 보이되 플레이어 이동 시작점에 붙이지 않는다.

권장 배치:

- 벽면 선반
- 작업 테이블
- 낮은 보관대

바닥 한가운데는 피한다.

## 주의

R09는 복합 퀘스트다.

샘플 1개를 회수했다고 끝나는 것이 아니라 다음이 모두 필요하다.

- 외부 부유물 2개
- 진입구 청소
- 구역 마감
- C급 샘플 1개 회수

현재 데이터 에셋의 Phase 0이 아직 회수형 임시값이므로 진행 연결 수정이 필요하다.

# 6. X7-R10 — 생물 실험실 회수

## 위치

`B1-02 생물 실험실`

## 목표

B급 샘플 2개를 **Intact** 상태로 회수한다.

## 실제 사용하는 BP / DA

| 용도 | 실제 에셋 | 비고 |
|---|---|---|
| 퀘스트 데이터 | `/Game/Data/Quest/X7/Repeat/X7_R10` | 현재 Phase 1개 |
| 샘플 스폰 | `/Game/Blueprint/Sample/BP_QuestSampleSpawner` | 공용 스포너 |
| 생성 샘플 | `/Game/Blueprint/Sample/BP_SampleBase` | DA 등급 태그를 읽어 B급으로 생성 |
| 권장 전용 스포너 이름 | `BP_X7_R10_SampleSpawner` | 아직 프로젝트에 없음. 공용 BP를 자식/복제해 Arrow 2개 구성할 때 사용 |

### X7_R10 현재 데이터 실측값

| 항목 | 현재 값 | 최종 적용값 |
|---|---|---|
| Objective Type | `RecoverIntact` | 그대로 사용 |
| Required Count | `2` | 그대로 사용 |
| Accepted Grade | `Resource.Sample.Grade.B` | 그대로 사용 |
| Required Item Class | `None` | `None` 유지 시 스포너의 `BP_SampleBase` 사용 |
| Spawn Zone Tag | `Env.Zone.Mothership` | `Env.Zone.X7.Repeat.R10`으로 교체 필요 |
| HUD | `04·05·06 생물실험동에서 B급 샘플 2개를 Intact로 회수` | `B1-02 생물 실험실에서 B급 샘플 2개를 Intact로 회수`로 갱신 권장 |

현재 `Env.Zone.X7.Repeat.R10` 태그는 `DefaultGameplayTags.ini`에 아직 등록되어 있지 않다. 실제 적용할 때 태그 등록과 `X7_R10` DA 수정이 먼저 필요하다.

## BP_QuestSampleSpawner 세팅값

공용 BP의 현재 기본값은 다음과 같다.

| Details 항목 | 공용 BP 기본값 | R10 배치값 |
|---|---:|---:|
| Sample Class | `BP_SampleBase` | 유지 |
| Samples To Spawn | `1` | **`2`** |
| Spawn Zone Tag | `None` | **`Env.Zone.X7.Repeat.R10`** |
| Occupied Check Radius | `80 cm` | `80 cm` 유지 |
| Spawn Protection Duration | `3.0 s` | `3.0 s` 유지 |

등급 B는 스포너에서 직접 지정하지 않는다. `X7_R10`의 Accepted Grade가 B이므로 생성 시 `BP_SampleBase.Grade = B`로 설정된다.

### Spawn Point 2개 구성

공용 `BP_QuestSampleSpawner`는 기본적으로 `DefaultSpawnPoint` Arrow 1개만 가진다. `Samples To Spawn = 2`만 바꾸고 그대로 쓰면 두 샘플이 같은 위치에 겹칠 수 있다.

따라서 R10은 전용 자식 또는 복제 BP를 하나 만드는 것을 권장한다.

- 권장 이름: `BP_X7_R10_SampleSpawner`
- 부모: `BP_QuestSampleSpawner`
- 기존 `DefaultSpawnPoint`를 첫 번째 위치로 사용
- Arrow Component `SpawnPoint_02` 1개 추가
- `Samples To Spawn = 2`
- `Spawn Zone Tag = Env.Zone.X7.Repeat.R10`
- `Sample Class = BP_SampleBase`

Arrow 두 개는 각각 다른 배양 챔버 선반에 배치한다.

## 스포너 배치

`BP_QuestSampleSpawner` 1개를 생물 실험실 안에 배치한다.

| 항목 | 값 |
|---|---|
| Samples To Spawn | 2 |
| 등급 | B |
| Spawn Point | 2개 |
| 권장 Zone | `Env.Zone.X7.Repeat.R10` |

## Spawn Point 위치

두 샘플은 **배양 챔버 열**에 각각 떨어뜨린다.

권장:

- 챔버 A 선반 / 받침대
- 챔버 B 선반 / 받침대

두 샘플을 한 챔버 안에 겹쳐 두지 않는다.

## 로어와 구분

같은 방에 로어 `X7-L03`가 있다.

- R10 샘플: 배양 챔버 열
- L03 기록물: 넘어진 랙 아래

둘의 위치를 명확히 분리한다.

## 학습용 칸막이

B1-02에는 “부수면 길이 열린다” 학습용 칸막이 1개를 둔다.

샘플이 칸막이 뒤에 있을 수는 있지만, 두 샘플 모두 완전히 같은 사각에 몰아넣지 않는다.

# 8. X7-R02 — 표본 보관실 잔여 표본 수집

# 9. X7-R05 — 냉각 시스템실 진입로 확보

## 위치

`B1-05 냉각 시스템실`

단, **주 구획이 아니라 부속 구획**이다.

## B1-05 구역 구분

1. 주 구획 — 압축기 / Day3 M03b 냉각펌프
2. 부속 구획 — R05 대상
3. 배관 뱅크 뒤 — 땅굴 입구 후보

R05가 사용하는 것은 **2번 부속 구획**뿐이다.

## 필요한 배치

- 막힌 격벽 1세그먼트
- 청소 가능한 부속 구획 섹터
- `BP_MD_SectorCloseoutMarker`

## 격벽

- 내력벽이 아닌 일반 철거용 칸막이
- 한 세그먼트만 제거하면 진입 가능
- 주 출입구를 막지 않는다

## 마감 마커

격벽을 제거하고 구획 청소 조건이 충족된 뒤 사용할 수 있는 위치에 둔다.

권장:

- 부속 구획 출입구 바로 안쪽
- 작업 완료 후 돌아보면 눈에 들어오는 벽면

## 절대 금지

**B1-05 주 출입구를 R05용 벽으로 막지 않는다.**

R05가 추첨되지 않은 계약에서도 Day3 M03b 플레이어는 냉각펌프에 접근할 수 있어야 한다.

## 현재 구현 상태

현재 R05 데이터 에셋은 회수형 임시값이 남아 있다.

샘플 스포너를 배치하지 않는다.

철거 + 섹터 마감 진행 연결이 구현된 뒤 최종 검증한다.

# 10. X7-R06 — 바다 오염 조사

## 위치

모선 ↔ 01 진입구 사이 **진입 항로**

## 목표

해수 스캔 포인트 3개.

## 배치 원칙

세 지점을 한눈에 몰아두지 않는다.

권장 동선:

1. 모선 출발 후 초반
2. 항로 중간
3. 01 진입구 접근 구간

플레이어가 자연스럽게 전진하면서 1 → 2 → 3 순서로 찾을 수 있게 한다.

## 스캔 지점 간 거리

너무 가깝게 붙이지 않는다.

세 지점 각각이 “다른 오염 위치를 조사한다”는 느낌이 나야 한다.

## 도구

기본 지급 스캐너 `IT-S0` 사용.

별도 유료 장비를 강제하지 않는다.

## 현재 구현 상태

현재 프로젝트에서 반복 전용 해수 스캔 포인트 BP가 명확하게 확인되지 않았다.

따라서 최종 액터가 준비되기 전에는:

- 임시 TargetPoint를 위치 마커로 써도 됨
- 최종 커밋에서는 전용 스캔 액터로 교체
- `BP_QuestSampleSpawner`로 대체하지 않음

현재 R06 데이터 역시 회수형 임시값이라 진행 타입 수정이 필요하다.

# 11. X7-R07 — 떠다니는 폐기물 수거

## 위치

**침몰 잔해 지대**

## 목표

표류 잔해 5개 수거 후 현장 대기장에서 정분류.

## 폐기물 배치

5개를 한 덩어리로 놓지 않는다.

권장 분포:

- 낮은 잔해 주변 2개
- 수영으로 접근해야 하는 중간 높이 2개
- 조금 떨어진 외곽 1개

최소 1개는 접지 이동만으로 바로 집을 수 없는 위치에 둔다.

## 분류장

현장 대기장의 5색 분류 칸을 사용한다.

잔해는 금속·플라스틱 혼합으로 구성할 수 있다.

의뢰 카운트는 지정 잔해의 올바른 분류 완료를 기준으로 연결한다.

## 임시 쓰레기통

5개뿐이므로 임시 쓰레기통 1개면 충분하다.

## 땅굴 출구와 거리

향후 땅굴 출구 후보 지점과 겹치지 않게 한다.

땅굴 출구는 잔해 지대 가장자리 쪽으로 남겨 둔다.

## 현재 구현 상태

R07도 현재 데이터가 회수형 임시값이다.

일반 샘플 스포너를 놓지 않는다.

지정 잔해 5개의 퀘스트 귀속과 분류 완료 진행 연결이 준비된 뒤 최종 검증한다.

# 15. PIE 체크리스트

## 공통

- 선택되지 않은 반복 퀘스트 대상이 잘못 활성화되지 않는가
- Accepted 이후 필요한 스폰물만 생성되는가
- 계약 Day가 넘어가도 미회수 스폰물이 유지되는가
- 실제 계약 종료 전에는 반복 퀘스트가 Failed 처리되지 않는가

- R09 C 1개
- R10 B 2개
- R11 A 1개
- R02 2개
- R08 2개

4. R07의 ObjectiveType을 지정 폐기물 분류 진행으로 연결
5. R09 Phase 0의 청소·마감 진행 연결 수정
6. R10 / R11 / R02의 구 HUD 위치명 최신화

이 작업 전에는 배치 위치가 맞아도 퀘스트 스폰/진행 결과가 기획과 다를 수 있다.
