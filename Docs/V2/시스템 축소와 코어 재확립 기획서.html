제거 범위를 넓혀 해석하지 않는다

  • 로어 수집, 기록물, 코덱스, 이미 수집한 개인 기록은 유지한다. 메인·반복퀘스트와 공용 데이터·UI·저장 경로를 쓴다는 이유로 함께 제거하지 않는다.
  • 벽 헤라질 제거는 벽 표면을 긁어 청소하는 작업 루프를 없애는 결정이다. 따개비 제거, 헤라 도구 전체, 액체 쓰레기통, 산재 쓰레기·분류를 모두 없애자는 결정까지 전달받은 것은 아니다. 각각의 존폐는 별도 확인한다.
  • 지지대와 지주격벽 전용 규칙은 제거한다. 공용 벽 파괴·절단·잔해·충돌·상호작용까지 지우지 않는다. 벽 파괴의 최종 입력과 방식은 새 코어에서 정한다.
  • DAY 제거 뒤에도 플레이 시간 제한을 둘지, 현장 종료를 어떻게 할지는 미정이다. 새로운 타이머나 라운드를 대신 넣지 않는다.
  • 상점, 대출, 산소, 스캐너, 샘플, 수리, 위험 존, 점수·크레딧, 저장 전체가 삭제된다는 결정은 없다. 남길 기능과 연결 변경을 검토한다.

새 기획에서 더 이상 요구하지 않는 것

메인/반복 의뢰 수락·진행·납품·완료 대사·보상, Day1~3 메인 목표, 퀘스트 단계별 안내 스플라인·외곽선, 반복 추첨·스포너 태그는 새 필수 콘텐츠로 배정하지 않는다. 관련 랙·캐비닛·샘플·냉각펌프는 재사용 여부를 먼저 정한다. 모델이 있다는 이유로 원래 의뢰를 유지하거나, 의뢰가 없어진다는 이유로 모델을 즉시 삭제하지 않는다.

3일 계약, 일차별 언락·착수금·정산·복귀·점검, 경고 다음날 배율, 비상 Day4와 그 점수 목표는 기존 DAY 규칙이다. 새 시스템의 요구사항이나 수정 과제로 그대로 가져오지 않는다. 시간대에 따른 하늘 표현과 음성·온라인 등은 DAY와 연결되어 있어도 별도 기능이므로 영향 분석 후 처리한다.

벽 청소율, 벽 청소 보상, 벽 오염 적재·역오염, 지지대 구매·설치·강도, 지주 하중·천장 지지·지주 붕괴 판정은 제거 범위와 연결된 구판 규칙이다. 벽 파괴의 잔해·통행과 공용 저장/복제 기능을 남기는 작업과 분리한다.

문서와 구현 상태를 구분한다

이번 반영은 기획·작업 목록·HTML 갱신이다. 소스·BP·데이터 에셋·맵에서 시스템을 실제 제거한 상태가 아니다. 기존 구현이 남아 있는 것은 담당 작업이 진행되기 전의 기준 상태다.

구판 문서는 삭제하지 않고 상단에 적용 범위 변경 안내를 붙인다. 기존 수치·배치·대사는 새 필수 요구사항이 아니다. 코어가 확정되면 관련 구판 내용을 대체한다. 소설과 로어 본문은 시스템 제거를 이유로 다시 쓰지 않는다.

공동 검증 원칙

  1. 각 담당은 제거 전 공용 참조, BP 상속, UI 호출, 저장 필드와 복제 경로를 확인한다.
  2. 제거된 기능을 열거나 요구하는 화면·문구·맵 게이트가 남지 않도록 한다.
  3. 로어 발견·코덱스·기존 수집 기록, 벽 파괴·잔해·통행을 실제 플레이로 검증한다.
  4. 코드 빌드와 별도로 BP 컴파일·Cook·실행 빌드를 확인한다.
  5. 맵 배치는 지정된 담당이 통합한다. 이 작업에서 맵은 변경하거나 커밋·푸시하지 않는다. 사용자의 기존 맵 업로드 금지 지시를 유지한다.

확정된 출발점

메인·반복퀘스트, DAY, 벽 헤라질, 지지대, 지주격벽 규칙에 기대어 재미를 설명하지 않는다. 로어와 벽을 부수는 개념은 남긴다. 과거의 3일 계약 완주·퀘스트 수량·점검 목표를 새 핵심 목표로 다시 넣지 않는다.

현재 프로젝트에는 수중 협동 이동, 벽 파괴, 물리 운반·분류, 도구, 현장·모선, 로어 등의 재료가 있다. 기능이 구현돼 있다는 사실만으로 모두 새 코어에 포함되는 것은 아니다.

후보를 비교하는 방법

아래 후보는 회의 확정 사항이 아니다. 후보를 하나 골라 작은 장면에서 플레이해 본 뒤 규칙을 결정한다. 다른 후보를 동시에 대규모 구현하지 않는다.

후보플레이어가 반복하는 행동확인할 재미위험과 필요한 결정
벽 파괴와 물리 사고벽을 부수고 생긴 조각·상황에 대응파괴 결과의 손맛, 우발적 사건, 팀원 반응자르는 방식/부수는 방식, 사고가 벌점 스트레스가 되는지
길 열기와 물건 운반장애물을 부숴 경로를 바꾸고 물건을 옮김어떤 길을 열지 선택, 운반 협력, 물건의 물성운반·분류를 유지할지, 전달 위치와 종료 조건
자유 탐색과 발견구조를 열어 숨겨진 공간과 기록물을 발견내가 연 길과 발견의 관계, 협동 탐색로어를 강제 목표로 만들지 않고 반복 재미를 확보할 방법

먼저 확정할 질문

  1. 가장 재미있어야 하는 한 행동은 무엇인가? 벽 파괴인지, 운반인지, 탐색인지 한 문장으로 적는다.
  2. 플레이어는 왜 벽을 부수는가? 길을 열기, 물건을 얻기, 파괴 자체 등 목적을 선택한다.
  3. 세션은 어떻게 끝나는가? 자유 귀환, 현장 완료, 다른 조건 중 실제 방식과 판정을 정한다. DAY의 대체물을 자동 도입하지 않는다.
  4. 성공과 실패를 어떻게 이해하는가? 점수·손실·위험·보상 중 필요한 것만 선택한다. 기존 점검 수치를 재사용하지 않는다.
  5. 팀원이 함께할 때 달라지는 선택은 무엇인가? 둘이 함께해야 하는 일이나 서로 돕는 상황을 정한다. 단순히 인원을 늘린 결과와 구분한다.
  6. 무엇을 들고 남기는가? 쓰레기 분류·샘플·경제·도구·산소·수리·따개비·헤라 잔존 기능·저장 각각을 유지/수정/제거로 표시한다.

재미 확인용 작은 테스트 제안

테스트 장면의 범위·시간·수치는 제안이며 확정 기획이 아니다. 벽을 부수어 경로가 달라지는 작은 공간을 준비하고, 2명이 같은 목적을 수행하게 한다. 선택한 후보가 운반을 포함한다면 물건 하나와 두 경로 정도부터 시작한다. 본편 맵 확장이나 신규 보상 시스템을 먼저 만들지 않는다.

테스트는 퀘스트·DAY·벽 청소·지지대 없이 진행한다. 로어 하나를 선택적으로 발견하게 하되 찾지 않아도 테스트를 마칠 수 있게 한다. 플레이어에게 설명을 많이 해야 진행된다면 안내보다 행동의 목적이 불명확한지 먼저 확인한다.

관찰할 것은 플레이어가 스스로 벽을 부수려 하는지, 경로·도구 선택을 바꾸는지, 팀원에게 도움을 요청하는지, 반복하고 싶어하는 장면이 생기는지다. 테스트 후 재미있던 순간, 막힌 이유, 반복하면 지루할 행동을 구체적인 장면으로 기록한다.
