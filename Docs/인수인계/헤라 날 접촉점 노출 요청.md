# 헤라 날 접촉점 노출 요청
**대상 파일:** `Source/MarineDemolition/{Public,Private}/Component/Scrape/MD_ScrapeToolComponent.{h,cpp}`
**긴급도:** 낮음. 로컬 플레이어는 우회 구현으로 이미 동작합니다. 멀티에서만 막힙니다.

---

## 0. 한 줄 요약

헤라로 긁을 때 **날 끝을 실제 접촉 지점에 붙이는 IK**를 넣고 있습니다.
그 접촉 지점의 월드 좌표를 블루프린트에서 읽을 방법이 없어서, `GetCurrentScrapeContact()` 하나만 추가해 주시면 됩니다.

---

## 1. 왜 필요한가

### 지금 상태

`UMD_ScrapeToolComponent`는 매 프레임 시점에서 트레이스를 쏴서 표면 접촉 지점을 구합니다. 그런데 그 월드 좌표가 컴포넌트 밖으로 나오지 않습니다.

| 후보 | 왜 못 쓰는가 |
|---|---|
| `FMD_ScrapeResult` | 표면 로컬 2D 좌표(`FVector2D`)만 있고 월드 좌표가 없음 |
| `OnScrapeSurfaceApplied` | 위와 같은 `FMD_ScrapeResult`를 전달 |
| `ContactLocation` | `DispatchAuthoritativeScrapeResult` · `ClientReceiveScrapeResult`의 **인자**로만 오감 |
| `TryGetCurrentSurfaceHit` | `private` |

### 로컬은 우회했습니다

애님 블루프린트에서 **같은 트레이스를 다시 쏘는** 방식으로 붙여뒀습니다. 파라미터는 `MD_ScrapeToolComponent.cpp:20`에서 그대로 가져왔습니다.

```
시작    GetPlayerViewPoint의 ViewLocation
방향    시선 방향 × TraceDistanceCm (220)
채널    ECC_Visibility
무시    소유 폰
```

입력이 같으니 결과도 같습니다. 로컬 플레이어에서는 이걸로 충분합니다.

### 멀티에서 막힙니다

**다른 플레이어의 캐릭터는 내 클라이언트에 시점 정보가 없습니다.** `GetPlayerViewPoint`는 내 컨트롤러 것만 돌려주므로, 남의 헤라가 어디를 긁는지 재현할 수 없습니다. 그러면 **내 헤라만 날이 벽에 붙고 남의 헤라는 허공에 뜹니다.**

그런데 `ClientReceiveScrapeResult`가 이미 `ContactLocation`을 `FVector_NetQuantize10`으로 받고 있습니다. **그 값을 필드에 캐시만 해두면 시뮬레이티드 프록시에서도 그대로 쓸 수 있습니다.** 새 리플리케이션을 추가할 필요가 없습니다.

## 2. 요청 내용

### 2.1 헤더 — public

```cpp
/**
 * 이번 프레임 헤라가 닿은 표면 지점을 반환한다.
 *
 * 애니메이션이 날 끝을 이 지점에 맞추는 데 사용한다. 긁고 있지 않거나
 * 표면을 놓친 프레임에는 false를 반환하며 출력값을 건드리지 않는다.
 *
 * 서버와 로컬 클라이언트는 자신의 트레이스 결과를, 시뮬레이티드 프록시는
 * ClientReceiveScrapeResult로 받은 값을 사용한다.
 */
UFUNCTION(BlueprintPure, Category = "MD|Scrape")
bool GetCurrentScrapeContact(FVector& OutWorldLocation, FVector& OutWorldNormal) const;
```

### 2.2 헤더 — private

```cpp
/** 마지막으로 표면에 닿은 월드 위치. 접촉이 끊기면 무효로 표시한다. */
FVector LastContactWorldLocation = FVector::ZeroVector;

/** 그 지점의 표면 법선. 날의 기울기를 벽면에 맞추는 데 사용한다. */
FVector LastContactWorldNormal = FVector::ZeroVector;

/** 위 두 값이 이번 프레임 기준으로 유효한지 여부. */
bool bHasLastContact = false;
```

### 2.3 채우는 지점

| 경로 | 위치 | 값 |
|---|---|---|
| 서버 · 로컬 | `ProcessScrapeTrace`에서 `TryGetCurrentSurfaceHit`이 성공한 직후 | `Hit.ImpactPoint`, `Hit.ImpactNormal` |
| 원격 클라 | `ClientReceiveScrapeResult` | 인자로 받은 `ContactLocation` (법선은 없으니 `ZeroVector` 또는 생략) |

### 2.4 비우는 지점

`bHasLastContact = false`로 되돌리는 곳:

- `StopScraping()`
- `ResetStrokeTracking()`
- `ProcessScrapeTrace`에서 표면을 놓친 프레임

**비워주는 게 중요합니다.** 안 그러면 조준을 벽에서 뗐을 때 날이 마지막 지점에 붙어 있어서 팔이 이상한 자세로 굳습니다.

### 2.5 구현 예시

```cpp
bool UMD_ScrapeToolComponent::GetCurrentScrapeContact(
    FVector& OutWorldLocation,
    FVector& OutWorldNormal) const
{
    if (!bHasLastContact)
    {
        return false;
    }

    OutWorldLocation = LastContactWorldLocation;
    OutWorldNormal = LastContactWorldNormal;
    return true;
}
```

## 2.6 두 번째 요청 — 잠긴 스트로크 축

날의 방향을 판정과 맞추려면 **지금 가로로 긁는지 세로로 긁는지**를 알아야 합니다.

`FMD_ScrapeToolSpec`은 사각 브러시의 `BladeWidthCm`을 "이동 방향과 **수직**인 날의 가로 길이"로 정의합니다. 그런데 헤라 메시는 크로스헤드가 한 방향으로 고정돼 있어서, 가로로 긁든 세로로 긁든 날이 같은 방향입니다. **판정은 방향에 따라 폭이 바뀌는데 그림은 안 바뀝니다.**

세로 긁기를 기본으로 두고, 가로 긁기일 때 헤라를 축 방향으로 90° 돌리면 맞습니다.

```cpp
/** 이번 줄에서 고정된 긁기 방향. 가로면 true, 세로거나 아직 안 잡혔으면 false. */
UFUNCTION(BlueprintPure, Category = "MD|Scrape")
bool IsStrokeAxisHorizontal() const
{
    return bHasLockedStrokeAxis
        && FMath::Abs(LockedStrokeAxis.X) >= FMath::Abs(LockedStrokeAxis.Y);
}

/** 이번 줄의 긁기 방향이 정해졌는지 여부. */
UFUNCTION(BlueprintPure, Category = "MD|Scrape")
bool HasLockedStrokeAxis() const { return bHasLockedStrokeAxis; }
```

기존 private 멤버를 그대로 읽기만 하므로 로직 변경이 없습니다.

**우회 방법은 있습니다.** `ConstrainLookInput`이 잠긴 축의 수직 입력을 0으로 만들기 때문에(`MD_ScrapeToolComponent.cpp:96~106`), 컨트롤 회전의 프레임 변화량만 봐도 어느 축인지 거의 정확히 읽힙니다. 지금은 그렇게 붙여둡니다. 다만 `DirectionLockThresholdCm`(1cm) 도달 시점과 `BreakStrokePerpendicularDistanceCm`(8cm) 초과로 축이 풀리는 시점을 우리 쪽에서 다시 추정해야 해서, **축이 바뀌는 순간이 실제 판정과 한두 프레임 어긋납니다.** 90° 회전이 눈에 보이는 동작이라 어긋나면 티가 납니다.

## 3. 우선순위

법선(`OutWorldNormal`)은 **없어도 됩니다.** 날의 기울기를 벽면에 맞추는 데 쓰려던 건데, 부담되시면 위치만 주셔도 지금 구현은 돌아갑니다.

원격 클라 경로(`ClientReceiveScrapeResult`)도 나중에 붙이셔도 됩니다. 순서는:

1. **잠긴 스트로크 축 (§2.6)** ← 게터 두 줄. 가장 싸고 효과가 가장 큽니다
2. **접촉 위치 + 서버/로컬 경로** ← 우회 코드를 걷어낼 수 있습니다
3. 원격 클라 경로 ← 멀티에서 남의 헤라가 제대로 보임
4. 법선 ← 날 기울기 마감

## 4. 별건 — 트레이스 거리와 도구 길이가 안 맞습니다

이건 요청이 아니라 **판단을 넘기는 사항**입니다.

헤라 메시(`SM_Scrapper`)를 실측했습니다.

| 항목 | 값 |
|---|---:|
| 도구 전체 길이 | 116.6cm |
| 손(`hand_r`)에서 날 끝까지 | **101cm** |
| 날(크로스헤드) 폭 | 23.9cm |
| `TraceDistanceCm` | **220cm** |

정점 9,182개를 Z축 구간별로 훑은 결과, 로컬 Z 0~10 구간이 폭 23.9cm의 크로스헤드(날)이고 Z 80~100이 손잡이입니다. 손은 손잡이 쪽을 쥐므로 날은 손에서 101cm 앞에 있습니다.

**문제:** 팔을 뻗어도 날 끝이 닿는 거리는 벽까지 최대 130cm 정도입니다. 그런데 판정은 220cm까지 들어갑니다. 즉 **130~220cm 구간에서는 오염막이 벗겨지는데 헤라는 벽에 닿지도 않습니다.**

지금까지는 즉발 처리라 티가 안 났지만, IK를 붙이면 그 구간에서 헤라가 허공을 긁는 게 눈에 보입니다.

**제안:** `TraceDistanceCm`을 120~130cm 근처로. 다만 판정 사거리는 그쪽 영역이라 결정은 넘깁니다. 그대로 두시겠다면 애니메이션 쪽에서 "닿는 척"으로 처리하겠습니다.

## 6. 확인 방법

`GetCurrentScrapeContact`를 넣으신 뒤:

1. 헤라를 들고 벽을 긁습니다
2. 애님 블루프린트에서 우회 트레이스를 그 함수 호출로 교체합니다
3. 날 끝이 같은 자리에 붙으면 성공입니다 — 우회 구현과 결과가 일치해야 합니다

멀티 검증은 리슨 서버로 2인을 띄워 **상대방 캐릭터의 헤라**를 봅니다. 지금은 그쪽 날이 허공에 뜹니다.
