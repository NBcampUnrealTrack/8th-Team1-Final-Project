# 12. 비상 4일차 (Develop)

2일차 점검은 통과했지만 3일차 점검에서 처음 실패한 팀에게 주는 마지막 하루다. 착수금은 없으며 남은 작업으로 기준 점수를 채워야 한다. 이미 경고가 있는 팀이 다시 실패하면 이 연장일은 열리지 않는다.

**문서 버전:** Develop v1 (신규 — `02` §10에 흩어져 있던 비상 4일차 규칙을 진입 판정과 가용 행동 중심으로 재편. 예외 3가지 확정 반영)

**이 문서가 비상 4일차의 기준 문서이다.** `01`·`02`·`03`·`04`·`05`·`07`·`09`의 비상 4일차 서술은 전부 여기를 참조한다. 어긋나면 이 문서를 따른다.

**관련 문서:** `02 시스템 기획` §10(점검 판정·경고) · `05 수치 기획` §0(기준 점수)·§0.1(난이도 배율)·§0.2(인원 배율) · `07 경제 시스템` §2(착수금) · `09 퀘스트 기획` §1.5(이월) · `04 UI 기획` §비상 4일차

## 0. 한눈에

**2일차 점검을 통과한 팀이 3일차에 처음 실패하면 하루를 더 준다.** 이 연장일이 비상 4일차다.

| | 값 |
|---|---|
| 진입 경로 | **1가지뿐** — Day3 실패 + 경고 없음 |
| 기준 점수 | 누적 **≥ 1380** (표준·4인) — 경고 배율 ×1.1 **미적용** |
| 착수금 | **0₡** |
| 작업 시간 | 08:00 ~ 18:00 (정규일과 동일) |
| 메인 퀘스트 | **없음** — 메인은 Day3까지가 끝 |
| 결과 | 성공 → 계약 클리어 / 실패 → 게임오버 |

> **의도** — 팀을 처형하는 날이 아니라, 깎인 점수를 되돌리는 마지막 정리 근무.
> 못 깬 퀘스트를 다시 깨는 날은 아니다.

## 1. 진입 판정

### 1.1 판정 흐름

| # | 상황 | 결과 |
|---|---|---|
| 1 | Day2 실패 | 경고 + 패널티 → Day3 진행 |
| 2 | Day3 성공 | **계약 클리어** |
| 3 | Day3 실패 + **이미 경고 있음** | **게임오버** |
| 4 | Day3 실패 + **경고 없음** | 경고 부여 + 패널티 → **비상 4일차 개방** |
| 5 | Day4 성공 | **계약 클리어** |
| 6 | Day4 실패 | **게임오버** |

```
Day1 ── 점검 없음
  │
Day2 ── 성공 ────────────────────┐
  └──── 실패 → 경고 + 패널티 ─────┤
                                 │
Day3 ── 성공 ──────────────→ 클리어
  ├──── 실패 + 경고 있음 ───→ 게임오버
  └──── 실패 + 경고 없음 ───→ 비상 4일차
                                 │
Day4 ── 성공 ──────────────→ 클리어
  └──── 실패 ────────────────→ 게임오버
```

### 1.2 경로가 하나뿐인 이유

**Day2를 통과한 팀만 4일차에 갈 수 있다.**

Day2에서 이미 경고를 받았다면 Day3 실패는 3번 경로(게임오버)로 빠진다. 즉 비상 4일차는
"사흘 내내 아슬아슬했던 팀"이 아니라 **"이틀은 멀쩡했는데 마지막에 무너진 팀"**을 위한 장치다.

한 계약에서 4일차는 **최대 1회**만 열린다. 경고는 계약당 한 번만 부여되므로(2번째 실패는 게임오버)
구조적으로 5일차는 존재할 수 없다.

### 1.3 진입 시점에 확정되는 것

Day3 18:00 정산에서 아래가 순서대로 처리된다.

| 순서 | 처리 | 비고 |
|---|---|---|
| 1 | Day3 메인 퀘스트 **Failed 확정** | 호감도·점수 델타 즉시 반영 (`09` §1.5) |
| 2 | Day3 메인 스폰물 **디스폰** | 4일차에도 예외 없음 → §3 |
| 3 | **경고 부여** | 계약당 1회 |
| 4 | 경고 패널티 적용 | 단 4일차에 미치는 효과는 §2.3 참조 |
| 5 | 비상 4일차 개방 | UI 안내 (`04` §비상 4일차) |

**반복 슬롯은 건드리지 않는다.** 비상일을 포함해 실제 계약 종료까지 Accepted 상태·진행도·스폰물을 유지한다.

## 2. 기준 점수

### 2.1 계산식

```text
Day4 기준 = 1380
          × 난이도 배율 (0.8 / 1.0 / 1.2 / 1.4)
          × 인원 배율   (0.40 / 0.65 / 0.85 / 1.00)
          ※ 경고 배율 ×1.1 은 곱하지 않는다
```

인원은 **계약 시작 시점으로 고정**된다. 도중 합류·이탈로 바뀌지 않는다 (`02` §10).

### 2.2 난이도별 (4인 기준)

| 난이도 | 배율 | Day2 | Day3 | **Day4** |
|---|---:|---:|---:|---:|
| 안전 | ×0.8 | 400 | 960 | **1104** |
| 표준 | ×1.0 | 500 | 1200 | **1380** |
| 위험 | ×1.2 | 600 | 1440 | **1656** |
| 극한 | ×1.4 | 700 | 1680 | **1932** |

### 2.3 인원별 (표준 난이도)

| 인원 | Day2 | Day3 | **Day4** |
|---|---:|---:|---:|
| 1인 | 200 | 480 | **550** |
| 2인 | 330 | 780 | **900** |
| 3인 | 430 | 1020 | **1170** |
| 4인 | 500 | 1200 | **1380** |

### 2.4 경고 배율을 빼는 이유 (확정)

4일차 진입 조건 자체가 "Day3 실패 → **경고 부여** + 4일차 개방"이므로
**4일차는 언제나 경고 상태**다. 여기에 ×1.1을 적용하면 진입한 전원에게
1380 대신 **1518**이 걸린다.

- 구제 취지와 정면으로 어긋난다 — 구제일이 정규일보다 어려워진다
- `05` §3A.2·§3B.2 시뮬레이션이 **1380 전제**로 계산돼 있다.
  특히 TR-9 표준 경로는 1477에서 끝나므로, 1518이면 **설계된 정답 루트가 실패**한다

경고 패널티의 나머지 항목도 4일차에는 사실상 적용되지 않는다.

| 경고 패널티 | 4일차 효과 |
|---|---|
| 다음 **정규일** 착수금 ×0.7 | **무효** — 4일차는 정규일이 아니고 착수금이 0 |
| 소모품 할인 제거 | 유효 (상점 이용 시) |
| 다음 점검 기준 ×1.1 | **미적용** (위) |
| 평가 점수 −40 | **4일차 시작 점수를 깎지 않는다** |

> 경고 패널티는 **정규일 전용**으로 읽는다. 4일차는 깎인 점수를 되돌리라고 여는 날인데
> 시작부터 더 깎으면 앞뒤가 맞지 않는다.

## 3. 4일차에 할 수 있는 것

### 3.1 가용 재원

| 재원 | 4일차 | 근거 |
|---|:---:|---|
| **반복 슬롯 스폰물** | 가능 | 비상일을 포함해 실제 계약 종료까지 맵에 남는다 (`09` §1.5) |
| **산재 쓰레기** | 가능 | 물리 오브젝트, 그대로 잔존 |
| **따개비 · 오염물** | 가능 | 헤라 대상, 그대로 잔존 |
| **미철거 세그먼트** | 가능 | 절단 대상, 그대로 잔존 |
| **구역 마감** | 가능 (+40) | `05` §2.4 |
| **정시 복귀** | 가능 (+25) | `05` §2.4 |
| 메인 퀘스트 | **불가** | §3.3 |

**4일차의 점수 회복은 청소·분리·마감과 반복 슬롯 잔여분으로만 이루어진다.**

### 3.2 경제 — 착수금만 0이다

`07` §2.2가 0으로 규정한 것은 **착수금**뿐이다. 나머지는 정규일과 같다.

| 항목 | 4일차 |
|---|---|
| 착수금 | **0₡** |
| 보유 크레딧으로 상점 구매 | 가능 |
| 분리 환급 | 정상 발생 |
| 대출 | 명시 제약 없음 → 가능 (`07` §5) |

실질 제약은 **그날 새로 들어오는 밑천이 없다**는 것이다. Day3까지 모은 크레딧과
이미 가진 장비로 버텨야 한다. 지지대·폼건 같은 소모품을 Day3에 다 써버렸다면
4일차에 살 돈이 부족할 수 있고, 그것이 이 날의 압박이다.

### 3.3 메인 퀘스트는 Day3까지가 끝 (확정)

**4일차에는 메인이 발주되지 않는다.** Day3의 미회수 메인 스폰물도 18:00에 그대로 디스폰된다.

이유 — 메인은 Day 하루짜리 라인이고(`09` §1.5) 4일차는 그 라인의 연장이 아니다.
실패한 메인을 4일차에 되살릴 수 있게 하면 **Day3의 18:00 마감이 무의미해진다.**
"오늘 못 챈 것을 내일 주우면 된다"가 성립하는 순간 Day 구분이 사라진다.

> 4일차는 **남은 일을 치우는 날**이지 못 깬 퀘스트를 다시 깨는 날이 아니다.

## 5. 종료 처리

| 결과 | 처리 |
|---|---|
| 누적 점수 ≥ 기준 | **계약 클리어.** 정규 클리어와 동일하게 정산 |
| 누적 점수 < 기준 | **게임오버.** 실패 계약의 자동·수동 저장과 불러오기 목록을 정리해 재개 차단. 개인 로어·설정·다른 계약 저장은 보존 (`02` §10.5) |

게임오버 시 세이브를 지우는 것은 세이브가 "실패 회피 수단"이 되지 않게 하기 위함이다 —
**실패는 실패로 확정된다** (`02` §10.5).

## 8. 미정 — 확인 필요

**2026-09-18 소스 대조:** 착수금과 게임오버 저장 정리는 아직 기획대로 연결되지 않았다. 위 체크리스트를 완료로 표시하지 않는다. 근거와 확인 절차는 [공통 15](15%20구현%20대조%20및%20플레이%20검증%20기획.md) §3·§5를 본다.

| # | 항목 | 메모 |
|---|---|---|
| 1 | 4일차의 **대출 이자** 처리 | `07` §5는 "일 이자율 × 일 정산"이다. 4일차도 하루로 세어 이자가 붙는지 명시 규정이 없다. 붙는 쪽이 자연스러우나 확인 필요 |

| 3 | 4일차 **정시 복귀 +25** 적용 여부 | 정규일과 같게 두었으나(§3.1) 명시 규정은 없다 |
