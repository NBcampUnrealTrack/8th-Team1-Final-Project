## 1. 전체 화면 흐름

```text
모선 허브
 ├─ 상인 / 상점
 ├─ 대출
 ├─ 미션/일차 준비
 │   ├─ 구역 확인
 │   ├─ 난이도 선택(계약 시작 시)
 │   └─ 퀘스트 수락
 ├─ 로드아웃 (핫바 장비만)
 └─ Day 출발
      ↓
모선에서 바로 수중 투입 (레벨 스트리밍)
      ↓
인게임 HUD (08:00~18:00)
  · 현장: 청소 / 철거 / 손·임시 쓰레기통
  · 현장 대기장: 5색 분리칸 · 모선 복귀: 샘플 납품 + 정산
      ↓
18:00 모선 출발 / 미복귀 확정
      ↓
일일 정산 리포트 (점수 트랙 + ₡ 트랙)
      ↓
호감도 / 해금 갱신
      ↓
Day2·Day3 현장 점검 (누적 점수 기준)
     ↓
(무경고 Day3 실패 시) 비상 Day4 — 점수 회복
     ↓
다음 날 계속 / 클리어 / 게임오버
```

## 2. 모선 허브

플레이어가 매일 가장 많이 보는 화면이다.

### 고정 표시
| 정보 | 예시 | 이유 |
|---|---|---|
| 현재 일차 | Day 2 / 3 · (비상 Day4) | 계약 진행 위치 |
| **누적 평가 점수** | 820 / 1200 | 장기 위기 = 점검 점수 (`05`) |
| 다음 점검 | Day3 · 기준 1200 (경고 시 ×1.1) | 목표 가시화 |
| 경고 상태 | 없음 / 경고(+패널티 적용중) | 게임오버 임박도 |
| 비상일 여부 | 정규 Day / 비상 Day4 | 착수금 0 · 점수 회복 안내 |
| 호감도 | +2.4 | 상점/착수금 |
| **보유 크레딧** | 17,500₡ | 구매/대출 판단 (`07`) |
| 현재 빚/이자 | 5,000₡ / 10% | 상환 압박 |
| 오늘 근무 | 08:00~18:00 | 규칙 상기 |
| 오늘 착수금 | 500₡ (경고 시 350₡) | 출발 전 확정 |
| 출발 버튼 | DAY START | 핵심 CTA |

## 3. 상점 UI

### 카테고리 (5탭 — `08` §1 카탈로그와 일치)
1. 도구 (헤라 · 절단기 · 스캐너)
2. 안전 (**지지대만**)
3. **유틸 수리 (절연테이프 · 폼건·폼 카트리지)**
4. 생존 (산소 캔 · 산소 확장 탱크)
5. 회수 (샘플 완충 패드)

> **카테고리 기준 문서은 `08` §1이다.** 이전 판의 7탭 안(도구/스캐너/안전/유틸수리/회수/소모품/모선 업그레이드)에서 아래를 정리했다:
> - **스캐너 → 도구에 통합.** 스캐너는 2종(IT-S0·IT-S1)뿐이라 단독 탭이 비어 보인다.
> - **소모품 → 생존으로 개칭.** `08` §1 명칭과 통일. 소모품은 여러 탭에 흩어져 있어(배터리=도구, 폼탄=유틸, 지지대=안전) 탭 기준으로 부적절하다.
> - **모선 업그레이드 삭제.** `07` §4 가격표와 `08` 카탈로그 어디에도 품목이 정의돼 있지 않아 빈 탭이 된다. 품목이 확정되면 되살린다.
> - **비매품은 탭이 아니다.** 쓰레기통(IT-B0)은 상점에 노출하지 않는다 (아래 UX 포인트 참고).

### 아이템 카드에 반드시 넣을 것
- 이름
- 가격 (**₡**)
- 한 줄 기능 설명
- 해금 상태
- 잠김 조건 — 실제 해금 값은 `07` §4 표가 기준 문서이다.  
  실 예시: `호감 ≥0 · 퀘스트 1회` (열선 헤라 IT-H2) / `호감 ≥+1` (고속 절단기 IT-C1) / `IT-H2 보유` (열선 배터리)

### 화면 구도 (10차 회의 확정)

```
┌──────────┬────────────────────────────────┐
│ 카테고리 │  아이템 목록 (스크롤)          │
│  (세로)  │   [아이콘] 이름                │
│  도구    │           한 줄 설명   [가격]  │
│  안전    │           해금 조건            │
│  유틸수리│   ...                          │
│  생존    │                                │
│  회수    │                                │
└──────────┴────────────────────────────────┘
   보유 크레딧 · 호감도            [뒤로]
```

- **좌측**: 카테고리 5탭을 **세로 목록**으로. 선택된 탭 강조
- **중앙**: 아이템 목록. 행 하나가 카드 하나
- **상태 표시**: 보유 크레딧·호감도만 (`07` §8.1). 상단 전용 바를 두지 않는다
- 우측 상세 패널은 **두지 않는다** — 카드에 필요한 정보가 이미 다 있어 중복이다

### UX 포인트
- 잠긴 아이템도 “다음에 뭐가 열리는지” 보이게
- **가격 표시 자리가 호버 시 구매 버튼으로 바뀐다.** 평소에는 정보(가격)를, 누를 의도가 생긴 순간에만 행동(구매)을 보여준다. 살 수 없는 품목은 호버해도 바뀌지 않는다 — 누를 수 있다는 잘못된 신호를 주지 않기 위해서다

### 상점 화면에서 뺀 안내 (10차 회의)

| 뺀 것 | 옮긴 곳 |
|---|---|
| `다음 해금까지 0.6` (호감도 옆) | **삭제** (`07` §8.1). 해금 조건은 아이템 카드에 이미 적히므로 상단 중복 표시가 불필요 |
| **쓰레기통은 상점 비매품** 안내 | **삭제.** 팔지 않는 물건을 상점에서 설명하는 건 화면 낭비다. 필요하면 **브릭스 대화** 또는 툴팁으로 알린다 |

쓰레기통 자체의 규칙(비매품 · 폐기물 대기장 무한 보급)은 `08` §5.3이 기준 문서이며 변경 없다. 상점 화면에서 **안내 문구만** 뺐다.

## 5. 미션 / 난이도 / 퀘스트 UI

### 미션 카드
- 구역명: `X-7 B2 생물실험동`
- 계약 일수: `3 Day Contract`
- 현재 진행도: 개방 구역, 남은 샘플
- 점검 요약: `Day2 ≥OOO · Day3 ≥OOO` (Day4 `≥OOO`) — **난이도 배율과 인원 배율이 모두 적용된 최종 값**만 표시한다 (표준·4인 기준 500/1200/1380, `05` §0.1·§0.2)

### 난이도 카드 (계약 시작 시)
난이도가 바꾸는 건 점검 점수 목표뿐이다 (`02` §9, `05` §0.1) — 맵 콘텐츠·착수금·물가는 전부 동일. 카드에는 이것만 보여준다:
- 난이도 이름 (안전/표준/위험/극한)
- 점검 목표: `Day2 OOO · Day3 OOO · Day4 OOO`
- 한 줄 설명: "같은 현장, 더 높은 점수가 필요합니다"

### 퀘스트 카드 (= 반복 퀘스트 카드, §5.5 참고)
- 목표 (샘플 Intact 등) + **샘플 등급 배지** (C/B/A/S)
- 성공 시: **평가 점수 +N** · **퀘스트 보수 N₡** · **호감도 +N** — 3개를 한 줄에 나란히 (`09` §1.5 등급별 값)
- 실패 시: **평가 점수 −N · 호감도 −N** (크레딧 위약금 없음). 미회수보다 파괴가 더 크게 하락하므로 **두 값을 따로 표기**한다
- 수락/거절
- 안내: “샘플 의뢰를 완료하면 보상을 받습니다.”

> **표기 원칙:** 샘플 회수 퀘스트 카드는 성공/실패 수치가 **점수·₡·호감도 세 항목**이라, 기존 “호감도만” 표기로는 손해가 안 읽힌다. 실패 시 감소하는 두 값(점수·호감도)을 반드시 함께 보여준다.

> 이 카드는 **반복 퀘스트 전용**이다. 메인 퀘스트·로어 퀘스트는 완전히 다른 화면이 필요하다 — §5.5.

## 5.5. 퀘스트 목록 화면 (3탭, 신규)

### 왜 탭이 3개인가
퀘스트는 **메인 / 반복 / 로어** 3종류뿐이고 (`09` §0), 서로 **상호작용 모델이 완전히 다르다.**  
하나의 “퀘스트 카드” 컴포넌트를 셋 다에 재사용하면 안 된다 — 탭마다 리스트 형태·버튼·상태 표시를 따로 설계해야 한다.

### 탭별 차이 한눈에

| 탭 | 데이터 원천 | 리스트 형태 | 항목 상태 | 수락/거절 | 진행도 |
|---|---|---|---|---|---|
| **메인퀘** | `09` §1, `10` §2 (Day별 고정) | Day1/2/3 세로 3줄 고정 | 완료 / 진행중 / 잠김 | **없음** (자동 활성) | 하위목표 체크 |
| **반복퀘** | `09` §4, `10` §3 (계약당 2~3개 랜덤) | 카드 2~3개 | 제시 / 수락 / 진행중 / 완료 / 실패 | **있음** (개별 수락·거절, 수락 후 포기 가능) | N/M 진행도 |
| **로어퀘** | `09` §5, **`X-7 …/06`** (현장 고정 배치, 발견형) | 현장 전체 목록 (X-7 기준 7개) | 미발견 / 발견 / (일부) 암호화됨 | **없음** (자동 등록, 아이템처럼) | 전체 완성률 N/7 |

### 탭1: 메인퀘
- Day1/2/3을 항상 세로로 나열한다. **현재 Day만 펼쳐진 카드**로 하위목표(외부/내부 서브목표 등)를 보여주고, 지난 Day는 완료 체크, 다음 Day는 잠김(회색 처리)으로 표시한다.
- **수락/거절 버튼이 없다.** 그 Day가 되면 자동으로 활성화되는 목표다.
- 완료하지 않아도 다음 Day 진행에는 영향이 없다(`09` §1). UI에서도 강제로 막지 말고 “미완료” 배지만 남긴 채 계속 보이게 한다.
- 같은 현장을 재방문해도 항상 **동일한 라인**이 나온다 — 매번 다시 확인할 필요 없이 익숙한 목록이어야 한다.

### 탭2: 반복퀘
- 기존 §5 “퀘스트 카드” 스펙을 그대로 쓴다.
- 계약당 2~3개 카드가 제시되고(현장 2회차 방문부터, `09` §4), **카드별 개별 수락/거절** 버튼이 있다.
- 수락 후: 진행도 `N/M` 표시 + **포기(파기) 버튼** 노출. 포기 시 확인 팝업(“포기하면 호감도가 떨어집니다”).
- 미수락 카드는 계약이 끝나도 실패 처리되지 않는다 — 조용히 사라진다 (`07` §3.2 규칙1).
- 완료/실패 결과는 **호감도만** 반영한다. 크레딧 위약금은 없다.

### 탭3: 로어퀘 (코덱스)
- **수락/거절 개념 자체가 없다.** “지금까지 발견한 기록물 목록”일 뿐이다.
- 미발견 항목은 `???` 잠김 아이콘, 발견하면 이름·내용이 공개된다.
- 상단에 **전체 완성률 바** (`N/7`, 현장별로 총 개수 다름).
- 일부 항목(X-7의 “심해 신호 기록”, **`X-7 …/06`** X7-L07)은 발견해도 곧바로 안 열리고 **“암호화됨”** 으로 표시되다가, 나머지를 다 모으면 자동으로 해독된다 — 잠금 아이콘은 **미발견 / 발견(암호화) / 해독됨** 3단계로 표시해야 한다.
- **카피 전문·상세 패널 구조·상태별 문구는 `X-7 …/06` §7이 기준 문서이다.** 본문이 이야기 형식(8~16줄)이라 **상세 패널에 `ScrollBox`가 필요**하고, 목록과 상세는 각각 독립 스크롤이어야 한다 (`06` §7.4).
- 실패·포기 개념이 없다. 파괴되지 않는 한 언제든 재방문해서 주울 수 있다.

### 공통 주의
- 패널 타이틀을 탭 공통으로 “퀘스트 목록”이라고 고정하지 않는다. 탭에 따라 바뀌는 게 자연스럽다 — 예: 로어퀘 탭에서는 “기록 보관함(코덱스)”처럼, 퀘스트라기보다는 **수집물 목록**에 가깝게 표기한다.
- 세 탭 다 **점검(Day2/3/4) 통과와 무관한 보너스**다 (`09` §0 원칙1). 이 사실이 UI에서도 드러나야 오해가 없다 — 예: “점검엔 영향 없음” 같은 보조 문구.

### 헤라 오염 적재 표시 (`02` §1.2)

**주 표현은 UI가 아니라 헤라 날의 오염물 메시 3단계다.** HUD는 보조 역할만 한다.

| 요소 | 규칙 |
|---|---|
| 위치 | 핫바의 **헤라 슬롯 아이콘 위에 얇은 링/바** — 별도 패널을 만들지 않는다 |
| 색 | 1단계 흰 → 2단계 **노랑**(`#F5C400`, 오염 칸 색과 통일) → 3단계 **적색 점멸** |
| 3단계 진입 시 | 짧은 토스트 **"헤라 포화 · 비워야 닦인다"** 1회. 반복 표시하지 않는다 |
| 100 도달 시 | 아이콘 **적색 고정** + 긁을 때마다 `오염만 묻는 중` 짧은 경고 |
| 털어내기 1회 | 게이지가 **−20씩 눈에 띄게 뚝 떨어진다.** 부드러운 보간을 넣지 않는다 — 한 번의 조작이 한 칸을 지우는 게 보여야 반복 동작에 손맛이 붙는다 |
| 3단계 벗어남 | 적재 66 이하 진입 시 아이콘 적색 해제 (2회 털면 도달) |

> 게이지를 화면 중앙이나 상태바에 두지 않는 이유: 청소 중에는 시선이 **표면과 헤라 날**에 가 있다. 날 메시가 이미 상태를 말해주므로, HUD는 "숫자로 확인하고 싶을 때"만 보는 위치에 둔다.

### 상황형 팝업
- 지주격벽 감지
- **전선 교차 / 수도관 교차** (절단 조준 시)
- **전원 차단** (전선 절단 → 암전)

- **헤라 포화** (적재 67 진입 시 1회) / **헤라 세척 완료**
- 배관/과열 경고
- 17:00 철수 권고
- 17:30 강력 경고
- 샘플 Intact/손상 확정
- 천장 붕괴 (점수 −200 · 과태료 250₡) — 지지대 설치 상태에서는 발생하지 않음
- 쓰레기통 전도·쏟음
- 전선 수리 완료 / 수도 밀봉 완료
- **사망 → 부활** (즉시 리스폰, 평가 −30 안내 · 죽은 자리에 오염물 생성됨 안내)

### 스캔 오버레이
아이콘·라인만으로 읽히게:
- 칸막이격벽
- 지주격벽
- **전선** (앰버/노랑 라인)

## 7. 현장 대기장 분리 UI (5색)

현장은 섞어 담기만, **모선에서만** 분리한다.

| 칸 | 라벨 | 색 |
|---|---|---|
| 금속 | Metal | 실버 |
| 일반쓰레기 | General | 흰 |
| 플라스틱 | Plastic | 파랑 |
| 오염된 쓰레기 | Contaminated | 노랑 |
| 안타는 쓰레기 | Non-combustible | 회색 |

### UX
- 투입 시 즉각 피드백: `+20점 · +8₡` / `오분류 −12점`
- 오염계를 비오염 칸에 넣으면 **강조 경고** (−24점)
- 샘플 납품 패널은 분리 UI와 별개다 (납품은 모선):  
  - 납품 순간에는 **점수·₡가 뜨지 않는다** — `퀘스트 목표 1/2 달성` 같은 **진행도만** 표시
  - 퀘스트 조건을 모두 채운 순간 `퀘스트 완료 · 점수 +N · +N₡ · 호감도 +N` 을 한 번에 표시 (`09` §1.5)
- 18:00 전 미분류 잔여가 있으면 경고 배지

### 통째 투입 UX (`02` §1.5)

통을 컨테이너에 그대로 부을 수 있다. **빠르지만 오분류 위험을 진다.**

| 상황 | 표시 |
|---|---|
| 투입 직전 | 확인 팝업 — `내용물 n개 투입 · 통은 회수되지 않습니다` |
| **샘플이 들어 있음** | **강한 경고** — `샘플 n개가 들어 있습니다` (사고 방지, 기본값은 취소) |
| **응고 안 한 액체 있음** | **강한 경고** — `오염물 액체 n.n 유닛이 점수 없이 사라집니다 · 응고제를 먼저 뿌리세요` |
| 투입 결과 | 정분류/오분류를 **한 번에 합산해 표시** — `정분류 6 (+128) · 오분류 2 (−24)` |

- 결과를 품목별로 한 줄씩 흘리지 않는다. 통째 투입은 "빠르게 끝내려고" 쓰는 기능인데 로그가 길면 목적과 어긋난다.
- **통이 사라진다는 사실을 반드시 사전에 알린다.** 통은 무한 보급이라 손실은 없지만, 모르고 버리면 다음 진입 때 당황한다.

## 9. 일일 정산 리포트

정산 화면에는 오늘 번 점수와 돈, 사고로 잃은 점수와 돈을 함께 보여 준다.  
**상단 탭 또는 2단 레이아웃으로 점수 / ₡를 분리**한다.

### A. 평가 점수 (점검용)
1. 분리 정분류 합 (+20/12/16/32/16 계열)
2. 철거 성공 보너스 (+15 / +30)
3. **샘플 회수 퀘스트** 성공 / 실패(미회수·파괴) — 납품 자체는 항목으로 뜨지 않는다 (`09` §1.5)
4. 구역 마감 · 청소·마감 계약 성공 점수 · 정시 복귀
5. 오분류 · 대기장 미분류 잔여 · 붕괴 · 미복귀 · 사망 차감
6. **오늘 점수 / 누적 점수 / 다음 점검 기준**

### B. 크레딧 ₡ (상점용)
1. 착수금
2. 분리 환급
3. 퀘스트 보수 / 위약
4. 평가 연동 보너스 (당일 점수 × 1₡)
5. 붕괴·미복귀·사망 과태료
6. 대출 이자 · 상점 지출
7. **오늘 순이익 · 보유 ₡**

### 읽기 순서
상단: 오늘 성공한 것  
중단: 깎인 것  
하단: 누적 점수 vs 점검 · 최종 ₡과 다음 날 상태

**표시하지 않음:** 폐기 게이지 증감, 철거 수당, 샘플 납품 현상금.

## 10. 현장 점검 UI

판정은 **누적 평가 점수**만. (표준·4인 기준 Day2 **500** / Day3 **1200** / Day4 **1380** — `05` §0)

> **화면에는 계산이 끝난 최종 기준값만 띄운다.** 난이도 배율(`05` §0.1)·인원 배율(`05` §0.2)의 곱셈 과정은 노출하지 않는다. 단, 4인이 아닐 때는 기준 옆에 인원을 작게 병기해 "왜 기준이 다른지"가 읽히게 한다 — 예: `누적 320 / 480 (2인 기준)`.

### 2일차
- 제목: `Day 2 Site Inspection`
- 표시: `누적 점수 XXX / 500` (4인 표준 · 인원에 따라 값이 달라짐)
- 결과:
  - 성공 → 다음 날 진행
  - 실패 → `WARNING` + 패널티 요약 후 Day3 진행

### 3일차
- 제목: `Day 3 Final Inspection`
- 표시: `누적 점수 XXX / 1200` (4인 표준 · 경고 상태면 기준 ×1.1 → 1320)
- 결과:
  - 성공 → 계약 클리어
  - 실패 + 경고 상태 → 게임오버
  - 실패 + 경고 없음 → 경고+패널티 후 `Emergency Day 4` 안내

### 비상 4일차
- 제목: `Emergency Day 4 — Score Recovery`
- 명시 문구:
  - 착수금 없음 (0₡)
  - 목표: **누적 점수 ≥ Day4 기준** (표준·4인 1380 — `05` §0.1 난이도 배율 · §0.2 인원 배율 적용)
  - 난이도 과도 상승 없음
- 성공 → 클리어
- 실패 → 게임오버

### 경고 패널티 표시 예시
- 다음 착수금 **×0.7**
- 소모품 할증/할인 제거
- 다음 점검 기준 **×1.1**
- 평가 점수 **−40** (`05` S−11)

제외 표시:
- 게이지 직접 상승 없음
- 호감도 하락 없음 (경고 자체로는)

### 클리어 요약에 보여줄 유지 데이터
- 크레딧 ₡
- 호감도
- 퀘스트 진행도
- 상점 해금
- 대출 잔액
- (참고) 누적 평가 점수 — 다음 기지로 넘어가면 리셋 여부는 메타 규칙에 따름
