# Day1 메인 퀘스트 안내 경로

현재 구현 기준: 2026-09-29. Day1 전력 복구의 실제 데이터 ID는 **Quest:X7-M02**이다. X7-M01은 Day2 서버 카트리지 회수다.

## 배치와 동작

최초 구현은 다음 세 구간으로 구성했다. 최근 플레이 검증 시 L_Ocean의 `Quests/Main/Day1/Navigation`에는 Power01과 Cartridge 경로만 남아 있었다. 두 번째 설비와 콘솔의 수리 조건은 유지되어 있으며, 별도 Power02 경로가 없어도 미수리 설비 두 개의 외곽선은 함께 표시된다.

| 액터 | 표시 조건 | 안내 구간 |
|---|---|---|
| BP_QuestNavigation_Day1_Power01 | 첫 설비가 Broken | X-7 해치 아래 진입 공간 → 첫 발전 설비 |
| BP_QuestNavigation_Day1_Power02 | 현재 맵에는 별도 경로 없음 | 최초 구현: 첫 설비 → 두 번째 설비 |
| BP_QuestNavigation_Day1_Cartridge | 두 설비 수리 완료, 콘솔 잠금 해제 | 발전실 → 통제실 카트리지 콘솔 |

첫 설비 `BP_MD_PowerConduit_MainQ1`은 콘솔을, 두 번째 `BP_MD_PowerConduitMainQ2`는 통제실 쪽 문을 해제한다. 두 번째를 먼저 수리하면 첫 설비 안내를 유지하고, 첫 설비까지 수리하면 바로 콘솔 안내로 넘어간다.

해당 퀘스트가 Day1의 활성 0번 페이즈일 때 현재 구간 하나를 항상 표시한다. 별도의 키 입력이나 스캐너는 필요 없다. 콘솔에서 카트리지를 실제 지급받아 `IsDumped`가 참이 되면 즉시 안내를 종료한다. 납품 전이라 HUD 진행도가 0/1이어도 경로는 다시 켜지지 않는다. 퀘스트가 잠김·실패·완료 상태이거나 다른 Day이면 표시하지 않는다.

현재 퀘스트의 미수리 설비 전체에 외곽선(Stencil 250)을 동시에 표시한다. 경로의 Repair Target과 Required Repairs를 함께 확인하므로 별도 안내 경로가 없는 두 번째 설비도 강조된다. 수리한 설비만 개별적으로 강조를 끄고, 모든 수리가 끝나면 콘솔을 강조한다. 조준을 벗어나도 퀘스트 강조는 유지되며 카트리지 회수 후 해제된다. 일반 조준 하이라이트와 퀘스트 강조를 별도로 관리하므로 퀘스트 강조가 끝나도 조준 중인 대상의 기존 하이라이트는 유지된다. 설비의 스캐너 강조는 기존 우선순위를 유지한다. 일반 파이프·설비 전체에 외곽선을 켜는 설정은 아니다.

## 경로 편집

공통 Blueprint는 `/Game/QuestNavigation/BP_QuestNavigationRoute`, 부모 C++ 클래스는 `MD_QuestNavigationRoute`다.

1. 레벨에서 해당 안내 액터를 선택한다.
2. `RouteSpline` 컴포넌트의 점을 이동하거나 추가한다. 화살표는 점의 순서대로 향한다.
3. 필요하면 Details의 `Rebuild Route`를 실행한다. 현재 배치는 벽 안으로 곡선이 휘지 않도록 Linear 점을 사용한다.
4. 레벨을 저장한다. 실제 이동 통로와 문을 따라 배치해야 한다. 런타임 자동 길찾기나 움직이는 장애물 우회는 수행하지 않는다.

현재 경로 높이는 Z=-4320이고, 첫 점은 (-400,-462960,-4320)이다. 시작 지점은 해치 아래 내부 진입 공간이며 모선부터의 수중 구간은 포함하지 않는다. 배치 시 문 액터는 통과 가능한 출입구로 취급하고, 나머지 장애물에 대해 반경 30cm 구간 검사를 수행했다.

## 설정 항목

| 항목 | 용도 |
|---|---|
| Quest Definition Id / Phase Index | 안내할 활성 퀘스트와 페이즈 |
| Required Day | 안내 Day. 0이면 Day 제한 없음 |
| Repair Target | 이 경로가 안내하는 고장 설비 |
| Required Repairs | 먼저 수리되어야 하는 설비 목록 |
| Guide To Terminal | 켜면 설비 대신 잠금 해제된 콘솔로 안내 |
| Terminal | 카트리지 획득 여부를 확인할 콘솔. 세 경로 모두 같은 콘솔 지정 |
| Line Width | 경로 두께(cm) |
| Route Material | 발광 재질. `/Game/QuestNavigation/M_QuestRoute`의 RouteColor로 조정 |
| Preview In Editor | 편집 중 경로 미리보기. 플레이 중에는 퀘스트 조건이 결정 |

표시는 복제된 GameState의 MerchantComponent와 설비·콘솔 상태를 0.2초마다 읽는다. 안내 액터가 퀘스트 진행, 수리 또는 아이템 지급을 수행하지 않는다. 경로 메시에는 충돌·내비게이션 영향·그림자가 없다. 이후 Day는 별도 목표 조건과 경로 배치를 추가해야 하며 이번에는 연결하지 않았다.

## 검증

전체 Editor 빌드와 Blueprint 컴파일을 통과했다. PIE에서 첫 설비 → 두 번째 설비 → 콘솔 전환, 실제 콘솔 상호작용으로 카트리지 지급 후 모든 경로 숨김을 확인했다. 반대 순서로 수리해도 이미 수리한 설비를 건너뛰었고, 다른 Day·페이즈 및 참조 누락 시 표시하지 않았다. 맵을 다시 불러온 뒤에도 3개 액터의 스플라인 점·대상 참조·충돌 설정이 유지됨을 확인했다. 설비 전환 검증에는 기존 DebugForceRepair를 사용했고, 별도의 멀티플레이 클라이언트 플레이는 검증하지 않았다. 검증 자료는 `Saved/Diagnostics/QuestNavigation_20260929`에 있다.
