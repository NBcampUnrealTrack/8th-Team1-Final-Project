## 0. 바르코AI가 리얼 사운드로 나오는 이유와 대책

### 왜 그렇게 나오나

생성 모델은 **실제 녹음 데이터로 학습**했다. `metal scraping`처럼 사물+동작만 쓰면 모델은 "그 사물의 실제 녹음"을 가장 그럴듯한 답으로 내놓는다. 우리가 원하는 캐주얼 스타일라이즈드(`01` §4)는 데이터 분포상 **소수**라서, 명시적으로 요구하지 않으면 나오지 않는다.

### 프롬프트 4단 구조 (고정)

```
[동작·재질]  +  [스타일 토큰]  +  [매체 토큰]  +  [공간 토큰]
```

| 칸 | 역할 | 예 |
|---|---|---|
| 동작·재질 | 무엇이 어떻게 | `thick slime scraped off a concrete wall` |
| **스타일 토큰** | 리얼 회피 (**필수**) | `stylized cartoon game sfx, hyperreal exaggerated foley` |
| **매체 토큰** | "게임에서 쓸 한 방"으로 규정 (**필수**) | `single short one-shot, punchy transient, clean tail, mono, dry` |
| 공간 토큰 | 수중 / 모선 | `underwater muffled, low-pass filtered` |

### 스타일 프리셋 (복붙용)

아래 표의 프롬프트는 모두 이 프리셋을 **뒤에 붙여 쓰는 것을 전제**로 짧게 적었다.

```text
[STYLE_WORLD] = stylized cartoon video game sound effect, hyperreal exaggerated foley,
                bright and playful casual sci-fi, clean synthesized layers,
                NOT a realistic field recording, no horror, no gore, no dialogue, no music,
                underwater muffled low-pass, mono, dry, no reverb tail

[STYLE_DRY]   = 위와 같고 "underwater muffled low-pass" 만 제거 (모선·정산·상점용)

[STYLE_UI]    = stylized casual sci-fi game UI sound, short synthetic blip,
                clean digital, soft plastic click, no voice, no music, mono, dry

[STYLE_AMB]   = stylized ambient game room tone, calm and clean, gentle underwater hum,
                no music, no melody, no creature vocals, seamless loop, stereo
```

사용법: `<표의 프롬프트>, [STYLE_WORLD]` 로 이어 붙인다.

### 회피 키워드 (넣으면 리얼로 끌려간다)

`realistic` · `real` · `field recording` · `documentary` · `raw` · `foley recording` · `ASMR` · `cinematic` · `horror` · `dark ambient` · `high fidelity` · 실제 제품명(`angle grinder`, `Dremel` 등)

### 유도 키워드 (스타일라이즈드로 끌어온다)

`stylized` · `cartoon` · `game sfx` · `arcade` · `chunky` · `snappy` · `bouncy` · `squishy` · `hyperreal exaggerated` · `synthesized` · `designed sound` · `mobile game` · `satisfying` · `juicy` · `punchy`

### 그래도 리얼하게 나오면 — 후처리 3수

1. **피치 ±3~5 반음.** 리얼감의 상당 부분은 실제 물체의 크기감이다. 올리면 장난감처럼, 내리면 만화처럼 된다.
2. **트랜지언트 강조 + 테일 컷.** 리얼 녹음은 어택이 뭉툭하고 꼬리가 길다. 어택을 살리고 0.3초 내로 자르면 게임 SFX가 된다.
3. **레이어링.** 생성물(질감) + 신스 원샷(어택·톤). 우리는 신스 레이어를 **MetaSound**로 붙이면 파라미터 구동까지 같이 얻는다.

### 프롬프트 실패 패턴

| 쓰지 말 것 | 이유 | 대신 |
|---|---|---|
| `scraping sound` | 너무 짧아 모델이 기본값(리얼)으로 감 | 재질·두께·속도까지 명시 |
| `underwater metal cutting` | 다큐멘터리풍 롱테이크로 나옴 | `single short one-shot` 을 반드시 넣는다 |
| `barnacle removal` | 학습 데이터에 거의 없어 노이즈가 됨 | `hard shell popping off a wall` — 물리 현상으로 번역 |
| 문장형 서술 | 앰비언스로 해석되는 경향 | 콤마 구분 키워드 나열 |
| `blade` | **검 뽑는 소리(sword unsheathe)로 나온다.** 학습 데이터에서 blade의 최빈값이 검이다 | 도구 이름을 직접 쓴다 — `electric chainsaw`, `putty knife` |
| `metal wall` / `metal panel` | 금속 클랭·판재 울림으로 나온다 | 벽은 **`concrete`**, 선체만 `metal hull` |
| `sparks` | 금속 그라인딩을 강하게 유도한다 | 벽 절단에는 넣지 않는다. `dust spray`, `grit` |
| `burst` / `blast` / `explosion` | **폭파음으로 나온다.** 파열·분출에 쓰면 물이 아니라 폭발이 된다 | `splitting open`, `surge`, `gush`, `rushing out` + `no explosion, no blast` |

### 재질 어휘 사전 (프롬프트 작성 시 고정)

프롬프트에서 대상의 재질을 잘못 쓰면 스타일 토큰으로도 못 막는다. 아래를 고정 어휘로 쓴다.

| 게임 내 대상 | 프롬프트 재질 | 절대 쓰지 말 것 |
|---|---|---|
| 칸막이격벽 · 지주격벽 · 보통벽 | `concrete`, `masonry`, `cinder block` | `metal wall`, `panel`, `sheet metal` |
| 벽 조각 (~10개) | `concrete chunk`, `rubble`, `broken masonry` | `metal chunk`, `scrap` |
| 천장 베이 | `concrete ceiling slab` | `metal ceiling` |
| **외벽 · 선체** | `metal hull` (여기만 금속) | — |
| 절단기 | `electric chainsaw`, `motor`, `chain` | `blade`, `saw blade`, `laser` |
| 헤라 | `putty knife`, `wide scraper` | `blade` |
| 바닥 | `metal floor`, `metal grating` (기지 바닥은 금속 맞음) | — |

> 벽은 콘크리트, **바닥과 선체만 금속**이다. 이 구분이 흐려지면 철거 사운드 전체가 금속으로 쏠린다.

### 우선순위: "중요도" → **플레이 검증 순서**로 재정의

기존 P0/P1/P2는 "얼마나 중요한가"였고, 그건 발주 순서를 정해주지 못했다. 실제로 필요한 건 **어떤 순서로 넣어야 다음 검증이 가능한가**다.

| 웨이브 | 정의 | 판정 기준 |
|---|---|---|
| **W1** | 없으면 **손맛 검증 자체가 불가** | 긁기·자르기·집기·이동 — `01` §3의 5대 손맛 |
| **W2** | 없으면 **플레이어가 규칙을 못 배운다** | 실패·사고·경고 — 룰을 소리로 학습하는 층 |
| **W3** | 없으면 **하루 루프가 안 닫힌다** | 분류·정산·시간·점검 (`02` §5, §11, §12) |
| **W4** | 폴리시 | 앰비언스·문·배리에이션 확장 |

**승격 / 강등 (기존 대비):**

| 항목 | 기존 | 변경 | 이유 |
|---|---|---|---|
| 시간 알림 (12:00~17:50) | P1 | **W2** | 18:00 마감이 이 게임의 유일한 실패 압박이다. 소리 없으면 규칙이 안 가르쳐진다 |
| 모선 5색 분류 | P1 | **W3** | 하루 루프의 종착점. 정/오분류 피드백 없으면 루프가 닫히지 않는다 |
| 헤라 적재·포화 | P0 | **W2** | 적재는 손맛이 아니라 **관리 규칙**이다. 긁기(W1) 다음 층 |
| 샘플 손상·파괴 | P1 | **W2** | 되돌릴 수 없는 실패 → 규칙 학습층 |
| 무전 클릭 | P1 | **W1** | 협동 게임이고 사망 중에도 마이크를 쓴다 (`01` §6.8) |
| 문 열림·닫힘 | P1 | **W4** | 없어도 검증 가능한 순수 폴리시 |
| 상점·상인 | P1 | **W3** | 모선 루프의 일부 |

### 바르코AI 생성 워크플로

1. 항목당 **4~6개 생성** → 스타일 맞는 것만 채택. 첫 생성이 리얼하게 나오면 **스타일 토큰을 프롬프트 앞으로 옮겨** 재시도한다.
2. 배리에이션은 같은 프롬프트를 재생성하기보다 **재질·강도 형용사만 바꿔** 생성하는 편이 톤 일관성이 높다.
3. 루프 소재는 생성물이 심레스가 아니다. **중간 3초 구간을 잘라 크로스페이드**해 루프화한다.
4. 채택 원본은 `Content/Audio/Raw/`에 보관하고, 후처리본만 `SFX/`로 올린다.
5. 같은 카테고리는 **하루에 몰아서 생성**한다. 세션이 바뀌면 톤이 튄다.

### UE 측 기술 전제

- **수중 필터를 에셋에 굽지 않는다.** Submix Effect Chain(LPF + Reverb)으로 처리하고 모선 진입 시 서브믹스 스냅샷을 전환한다. 프롬프트의 `underwater muffled`는 질감 유도용이고, 실제 공간감은 엔진이 만든다.
- 지속음(긁기 1·2·5·7·11, 절단 18·19, 수영 62)은 **MetaSound**로 진척도 → 피치·필터를 구동한다.
- **Sound Concurrency 필수 지정**: 벽 조각 착지(23), 발소리(57~60), 따개비(3), 정분류(99).
- 어테뉴에이션 프리셋 3종: 손안(근접 2D) / 방 안 / 섹터 밖 차폐.
