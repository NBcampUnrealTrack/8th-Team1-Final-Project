# 멀티유저 편집(Multi-User Editing) 운영 규칙

UE5.8 Multi-User Editing 플러그인을 Tailscale VPN 위에서 쓰기 위한 규칙이다.
호스트는 맥미니 1대 고정(상시 가동)이다.

이 플러그인은 Epic이 **Beta**로 표시하고 있고, 실제 사례에서 **데이터 손실과 에디터 크래시**가
보고되어 있다. 설정으로 막을 수 있는 건 이미 막아두었고(아래 "적용된 설정" 참고),
설정으로 못 막는 것들이 이 문서의 규칙이다.

**핵심 전제 — 이건 버전 관리 대체재가 아니다.** 특정 커밋 위에서 짧게 같이 작업하고,
끝나면 한 명이 커밋하고 세션을 버린다. 세션을 며칠씩 유지하지 않는다.

---

## 1. 해도 되는 것 / 하면 안 되는 것

플러그인은 **레벨 안의 액터 변경만 실시간 동기화**한다.
머티리얼·블루프린트·스태틱메시 같은 에셋은 실시간 동기화가 **안 된다** —
편집하는 동안은 나만 보이고, **저장하는 순간** 남들에게 통째로 전파되어
상대 에디터에서 핫리로드된다. 그래서 두 사람이 같은 에셋을 만지면 한쪽 작업이 날아간다.

### ✅ 세션 중에 해도 되는 작업
- 레벨에 액터 배치 / 이동 / 회전 / 스케일
- 액터 디테일 패널 속성 수정
- 라이트·볼륨 배치와 조정
- 시퀀서 작업
- 레벨 구성 논의하면서 같이 보기

### ❌ 세션 중에 하면 안 되는 작업
- **블루프린트 편집** — 컴파일/저장 시 통째로 덮어씌워진다
- **머티리얼 / 머티리얼 인스턴스 편집**
- **메시·텍스처 임포트** — 큰 파일이 VPN으로 한꺼번에 나가면서 세션이 끊어진다
- **레벨 자체를 새로 만들거나 삭제**

이런 작업이 필요하면 세션에서 나가서 평소처럼 각자 브랜치에서 하고 커밋한다.

#### "서로 안 겹치면 되지 않나?" — 안 통한다

엔진에 에셋 락이 있어서(`ConcertClientLockManager`) 두 명이 **같은** 에셋을 동시에
저장하는 것 자체는 막힌다. 그래서 대상만 갈라놓으면 될 것 같지만, 실제로는 세 군데서
터진다.

1. **저장하면 안 겹친 사람도 방해받는다.**
   에셋은 저장 순간 통째로 전파되어 상대 에디터에서 핫리로드된다. 그 BP 를 편집하지
   않고 **열어만 놔도** 리로드가 걸린다. `bInteractiveHotReload=True` 라 조용히
   덮어쓰이지는 않지만, 확인 창이 뜨면서 작업 흐름이 끊긴다.

2. **BP 컴파일이 레벨을 persist 범위로 끌고 들어온다.** ← 제일 위험
   블루프린트를 컴파일하면 레벨이 저장된다. 세션 중이면 그 저장이 샌드박스로 가면서
   **레벨이 persist 대기 목록에 들어간다.** 나중에 누가 `Persist Changes` 를 누르면
   남이 작업 중이던 레벨까지 같이 디스크로 나간다. 에셋은 안 겹쳤는데 레벨에서 겹친다.
   (실측: 액터 하나 스폰했을 뿐인데 `saved package /Game/Maps/...` 가 찍혔다)

3. **마지막에 Git LFS 락에서 막힌다.**
   멀티유저 락과 LFS 락은 서로 모른다. 세션 중엔 멀쩡히 작업되다가, persist 후
   커밋할 때 팀원이 그 `.uasset` 에 LFS 락을 걸어놨으면 거기서 멈춘다.

조건을 다 지키면(명시적 락 + 컴파일 금지 + 저장 전 통보 + LFS 락 확인) 불가능하지는
않지만, 지킬 것이 너무 많다. **에셋 편집은 원래 git 이 더 잘 다루는 영역이다.**
멀티유저가 잘하는 것은 레벨 액터 배치와 시퀀서다.

### 🤖 AI 에이전트 / MCP 자동화

세션 중 자동화를 통째로 금지하지는 않는다. 대신 **에디터 자동화를 실행하기 전에
가드레일을 통과**시킨다.

```python
import os, sys, unreal
sys.path.append(os.path.join(
    unreal.Paths.convert_relative_path_to_full(unreal.Paths.project_dir()),
    "Tools", "MultiUser"))
import mu_guard
mu_guard.assert_safe("compile_blueprint")   # 세션 중이면 예외를 던진다
```

- 세션 밖이면 아무 제약 없이 통과한다.
- 세션 중이면 아래 작업이 막힌다: `compile_blueprint`, `import_asset`, `save_all`,
  `delete_asset`, `create_landscape`, `modify_material`
  (`compile_blueprint` 가 막히는 이유: **레벨을 디스크에 저장한다**)
- 액터 스폰/이동은 허용되지만 로그로 한 번 경고한다. MU 가 정상 동기화하는 영역이다.
- 현재 상태만 보고 싶으면 `mu_guard.report()`.

**임시 산출물은 `/Game/_AgentScratch` 아래에 만든다.** 이 경로는
`Config/DefaultConcertSyncCore.ini` 의 `ExcludePackageClassFilters` 로 세션 전파에서
제외되어 있어, 에이전트의 중간 결과물이 남에게 쏟아지지 않는다.

에이전트가 세션을 관찰만 하게 하려면 별도 인스턴스를 띄운다.

```
Tools\MultiUser\Start-MU-Observer.bat <세션이름>
```

이 인스턴스는 표시 이름이 `<사용자명>-Agent` 라서 세션 히스토리에서 사람과 구분된다.
여러 팀원이 각자 AI 를 돌려도 누가 무엇을 바꿨는지 갈린다.

## 2. 세션 시작 전 체크리스트

한 항목이라도 어긋나면 붙어도 깨진다. 순서대로 확인한다.

1. **엔진 빌드가 전원 동일한가**
   전원이 아래를 실행해서 **엔진 지문 줄이 글자 그대로 같은지** 확인한다.
   다르면 접속은 되어도 트랜잭션이 어긋난다.

   - Windows: `Tools\MultiUser\Check-EngineVersion.bat`
   - macOS: `Tools/MultiUser/check-engine-version.command`

   지문 형식은 `Major.Minor.Patch-CompatibleChangelist-L<licensee>-<BranchName>` 이다
   (Concert 가 비교하는 값들 — `ConcertVersion.h` 의 `FConcertEngineVersionInfo`).

   우리 엔진은 **런처 설치본(Installed Build)** 이다 — `Engine/Build/InstalledBuild.txt`
   가 있고 `.git` 도 `.cpp` 도 없다. 그래서 git 커밋으로는 대조할 수 없다.

   지문은 같은데 `Changelist` 만 다르면 설치본과 소스 빌드를 섞은 경우다. 그때는
   Multi-User 설정의 **Support Mixed Build Types** 를 켜야 할 수 있다.

2. **활성 플러그인 구성이 전원 동일한가**
   Concert 는 엔진 버전 **외에** 활성 플러그인의 커스텀 버전 목록도 대조한다.
   엔진 지문이 같아도 플러그인 구성이 다르면 참가가 거부된다. 1번 스크립트로는
   **잡히지 않는** 종류다.

   ```
   Refusing user <이름> ... Invalid version for 'Dev-PoseSearch-Version'
   (expected '3', got '<none>'). Do you have a required plugin disabled?
   ```

   에러는 "플러그인을 비활성화하셨나요?" 라고만 해서 **어느 쪽 기계가 문제인지
   알려주지 않는다.** `<none>` 이 뜬 쪽에 그 플러그인이 꺼져 있다는 뜻이다.

   플러그인은 반드시 `MarineDemolition.uproject` 에 적어 커밋한다. 에디터에서
   개인이 켜면 그 기계에만 남고, 세션마다 재발한다.

3. **프로젝트가 전원 동일한 커밋인가**
   `git pull` 후 `git rev-parse --short HEAD` 를 비교한다. 세션은 이 커밋 위에서 시작한다.

4. **작업 트리가 깨끗한가**
   `git status` 에 수정본이 남아 있으면 세션 중 핫리로드로 날아갈 수 있다. 먼저 커밋하거나 치운다.

5. **대상 파일의 Git LFS 락이 풀려 있는가**
   멀티유저는 LFS 락을 모른다. 세션 중엔 잘 되다가 마지막에 커밋이 막힌다.
   `git lfs locks` 로 확인하고, 이번에 만질 레벨/에셋에 남의 락이 걸려 있으면 세션을 미룬다.

6. **VPN 접속 확인**
   전원이 같은 tailnet 에 있어야 한다. `tailscale status` 로 맥미니(호스트)가
   보이는지 확인한다. 런처가 알아서 바인딩하므로 주소를 외울 필요는 없다.

7. **방화벽 (최초 1회)**
   `Tools\MultiUser\Setup-MU-Firewall.ps1` 을 관리자 권한으로 한 번 실행한다.

## 3. 세션 실행 절차

### 호스트 = 맥미니 (상시 가동)

```bash
Tools/MultiUser/start-mu-server.command
```

**접속 경로는 Tailscale 하나뿐이다.** Radmin VPN 은 Windows 전용 제품이라 macOS 판이
없고, 호스트에 Radmin 주소가 없으면 Windows 팀원도 Radmin 으로는 닿을 수 없다.
그래서 `host.json` 의 transports 에는 tailscale 만 둔다. **radmin 을 되살리지 말 것** —
매 실행마다 ping 타임아웃만 발생한다.

서버는 `0.0.0.0:50002` 에 묶인다. 나중에 경로가 늘어도 서버 쪽은 고칠 것이 없다.

**런처 설치본이면 서버 실행 파일이 이미 들어 있다.** 따로 빌드할 필요 없다.
소스 빌드를 쓴다면 Program 타깃이라 기본 빌드에 없으므로 한 번만 빌드한다.

```bash
cd "$UE_ENGINE_DIR"
./Engine/Build/BatchFiles/Mac/Build.sh UnrealMultiUserSlateServer Mac Development
```

런처가 실행 파일을 못 찾는다고 하면 그때만 위 명령을 쓴다.

런처가 기동할 때 설정에 넣어야 할 값을 그대로 출력한다 — `host.json` 의 `hostMachine`,
그리고 `Config/DefaultEngine.ini` 의 `+StaticEndpoints`. 둘을 채워 커밋하면 팀원이 접속할 수 있다.

상시 가동이므로 맥미니가 잠들면 안 된다. 런처가 `caffeinate -s` 로 감싸 실행하지만,
**시스템 설정 > 에너지에서 자동 잠자기도 꺼두는 편이 안전하다.**

> **에디터가 서버를 자동으로 띄우게 두지 말 것.** 에디터 Multi-User 설정의 서버 자동
> 실행이 켜져 있으면, 에디터를 띄울 때마다 별도 서버가 하나 더 생긴다. 그 서버는
> `-CONCERTSERVER=RevStudio` 도 `0.0.0.0:50002` 바인딩도 없이 뜨기 때문에
> **UDP 포트를 하나도 열지 않고**, 팀원 목록에도 `RevStudio` 로 보이지 않는다.
> 맥 안에서만 쓸 수 있는 서버다. 실제로 이것 때문에 런처 서버가 죽고 세션이 끊긴 적이 있다.
>
> 서버는 항상 `start-mu-server.command` 로만 띄운다. 도는 서버가 맞는지는 이렇게 본다.
>
> ```bash
> pgrep -fl UnrealMultiUserSlateServer   # -CONCERTSERVER=RevStudio 가 보여야 한다
> lsof -nP -iUDP:50002                   # 비어 있으면 잘못 뜬 서버다
> ```

> Windows 쪽 `Start-MU-Server.bat` 은 이제 실행을 거부한다. `hostMachine` 이 맥미니로
> 지정되어 있기 때문이고, 의도된 동작이다. 서버가 두 대로 갈리면 세션이 쪼개진다.

### 참가자 전원

Windows:

```
Tools\MultiUser\Start-MU-Editor.bat
```

macOS:

```bash
Tools/MultiUser/start-mu-editor.command
```

런처는 자기 Tailscale 주소를 찾아 `-UDPMESSAGING_TRANSPORT_UNICAST=` 로 넘기고,
호스트 주소는 `Config/DefaultEngine.ini` 의 `+StaticEndpoints` 에서 읽는다.
런처가 설정 파일을 쓰지는 않는다.

에디터 툴바의 **Multi-User** 버튼 → Browser에서 `RevStudio` 서버 선택 → 세션 참가.

> 세션 중 연결이 끊기면: 에디터를 닫고 런처를 다시 실행한다. 주소가 바뀌었어도
> 런처가 다시 탐지해서 붙는다.

### macOS 참가자 주의

**맥에서 에디터로 세션에 참가하려면 Xcode 가 필요하다.** 프로젝트에 C++ 모듈이 있어서
맥용 바이너리를 직접 빌드해야 하고, Command Line Tools 만으로는 안 된다.

```
Platform Mac is not a valid platform to build. SDK validation failed:
  Sdk: not found. Required version 15.2.0.
```

최초 1회 준비가 세 단계다. 서버만 돌리는 호스트 역할에는 필요 없다.

```bash
# 1) Xcode 설치 후 툴체인 전환
sudo xcode-select -s /Applications/Xcode.app/Contents/Developer

# 2) 첫 실행 컴포넌트 (CoreSimulator 등). 이게 없으면 3번이 실패한다
sudo xcodebuild -runFirstLaunch

# 3) Metal 툴체인 — Xcode 26 부터 기본 설치에서 분리되었다
xcodebuild -downloadComponent MetalToolchain
xcrun metal --version          # 버전이 나오면 성공
```

3번이 빠지면 **에디터가 로그도 크래시 리포트도 남기지 않고 조용히 종료된다.**
셰이더 컴파일 단계에서 죽는 것이라 원인을 찾기 어렵다. CLI 다운로드가
`Failed fetching catalog` 로 실패하면 Xcode → Settings → Components 에서 받는다.

그다음 프로젝트를 빌드한다.

```bash
cd "$UE_ENGINE_DIR"
./Engine/Build/BatchFiles/Mac/Build.sh MarineDemolitionEditor Mac Development \
    -project="/Users/Shared/ATM/MarineDemolition.uproject"
```

> **맥 에디터 로그는 프로젝트의 `Saved/Logs/` 가 아니다.**
> `~/Library/Logs/Unreal Engine/MarineDemolitionEditor/MarineDemolition.log` 에 쌓인다.

Finder 에서 `.command` 파일을 더블클릭한다. 처음 한 번은 실행 권한이 필요할 수 있다.

```bash
chmod +x Tools/MultiUser/*.command
```

엔진 경로를 자동으로 못 찾으면 직접 지정한다.

```bash
UE_ENGINE_DIR=/path/to/UnrealEngine Tools/MultiUser/start-mu-editor.command
```

### 호스트 주소가 바뀌었을 때

`Config/DefaultEngine.ini` 의 `+StaticEndpoints` **한 줄만** 고치고 커밋한다.
런처도 이 값을 읽으므로 다른 곳에 같은 주소를 적을 필요가 없다.
(호스트 머신 자체가 바뀌면 `host.json` 의 `hostMachine` 도 같이 고친다)

맥미니에서 `start-mu-server.command` 를 실행하면 넣어야 할 값이 그대로 출력된다.

```ini
; Config/DefaultEngine.ini  - 주소와 포트
+StaticEndpoints=<맥 Tailscale IP>:50002
```

```json
// Tools/MultiUser/host.json  - 호스트 머신명만
"hostMachine": "<맥 호스트명>"
```

## 4. 세션 종료 절차

**여기가 제일 위험한 구간이다.** `Persist Changes` 는 크래시와 데이터 손실이
보고된 기능이므로(UE-86030) 순서를 반드시 지킨다.

1. **전원 편집 중단.** 액터를 잡고 있는 사람이 없어야 한다.
2. **전원 각자 저장** (`Ctrl+S` / Save All).
3. **호스트 한 명만** Multi-User 창에서 `Persist Changes` 실행.
   여러 명이 동시에 누르지 않는다.
4. 호스트가 `git status` 로 변경 파일을 확인하고 **바로 커밋**한다.
   persist 후 커밋까지 미루지 않는다 — 다음 세션이 덮어쓴다.
5. 커밋이 끝나면 **세션을 삭제**한다. 재사용하지 않는다.
6. 서버 창을 닫는다.

만약 persist 중 크래시가 나면, 각자 로컬에 저장된 내용이 남아 있으므로
당황하지 말고 **에디터를 다시 켜서 `git status` 부터 확인**한다.

## 5. 적용된 설정 (참고)

기본값으로 두면 VPN에서 터지는 것들을 미리 고쳐두었다. 임의로 되돌리지 말 것.

`Config/DefaultEngine.ini` → `[/Script/UdpMessaging.UdpMessagingSettings]`

| 설정 | 기본값 | 우리 값 | 이유 |
|---|---|---|---|
| `MaxSendRate` | 1.0 (1Gbit/s) | `0.02` (20Mbit/s) | 기본값은 VPN 업링크를 즉시 포화시켜 저장/임포트 중 세션이 끊긴다 |
| `MaxPacketSize` | 1130 | `1130` (명시 고정) | Radmin(어댑터 1500 + 캡슐화)과 Tailscale(WireGuard 실 경로 1280) 양쪽에서 단편화 없이 통과하는 값. 올리면 손실난다 |
| `ConnectionTimeoutPeriod` | 5초 | `30` | VPN 지터로 멀쩡한 연결이 끊기는 것 방지 |

`Config/DefaultConcertSyncCore.ini` → `[/Script/ConcertSyncCore.ConcertSyncConfig]`

| 설정 | 기본값 | 우리 값 | 이유 |
|---|---|---|---|
| `SnapshotTransactionsPerSecond` | 30 | `10` | 액터 드래그 한 번에 초당 30회 전송은 VPN에서 과하다 |
| `bInteractiveHotReload` | - | `True` | 남의 저장이 내 로컬 수정본을 말없이 덮어쓰는 것 방지 |
| `ExcludePackageClassFilters` | 없음 | `/Game/_AgentScratch` | AI 에이전트 임시 산출물을 세션 전파에서 제외 |

> `UConcertSyncConfig` 는 `config=ConcertSyncCore` 라서 반드시 `DefaultConcertSyncCore.ini`
> 에 있어야 한다. `DefaultEngine.ini` 로 옮기면 **오류 없이 조용히 무시된다.**

### 정적 엔드포인트 (Config/DefaultEngine.ini)

Tailscale 은 멀티캐스트를 나르지 않아 서버 자동 탐색이 **불가능하다.** 호스트 주소를
`+StaticEndpoints` 로 직접 찍어야만 붙는다.

```ini
+StaticEndpoints=100.77.222.84:50002
```

**호스트 주소와 포트는 여기가 유일한 출처다.** 런처도 이 파일을 파싱해서 쓰므로
`host.json` 에는 주소를 적지 않는다. 호스트가 바뀌면 **이 한 줄만** 고쳐서 커밋한다.

(`host.json` 에는 런처만 아는 것 — 서버 이름, 호스트 머신명, 어댑터 매칭, 서브넷
접두사 — 만 둔다. 어느 `+StaticEndpoints` 를 쓸지는 `subnetPrefix` 로 고른다.)

> **`Saved/Config/<플랫폼>Editor/Engine.ini` 에 쓰면 안 된다.** 에디터가 그 파일을
> **시작 시점에 통째로 덮어써서**, 써넣은 값이 읽히기 전에 사라진다. 에디터가 떠 있는
> 동안 파일을 열어보면 블록이 이미 없다. `StaticEndpoints` 는 커맨드라인 옵션도 없으므로
> 프로젝트 설정 파일이 유일한 주입 경로다.

머신마다 다른 `UnicastEndpoint` 는 런처가 `-UDPMESSAGING_TRANSPORT_UNICAST=` 로 넘긴다.

## 6. 문제가 생기면

| 증상 | 원인 |
|---|---|
| 서버 목록이 비어 있다 | `DefaultEngine.ini` 의 `+StaticEndpoints` 가 호스트 실제 주소와 다름. 호스트에서 서버 스크립트를 띄우면 실제 주소를 출력해 준다. 그다음으로 방화벽 |
| 런처가 "사용할 수 있는 VPN 경로가 없습니다" | 출력에 경로별 실패 사유가 나온다. 어댑터가 꺼졌는지, 호스트에 ping 이 안 닿는지 |
| 붙었다가 몇 초 만에 끊긴다 | VPN 연결 불안정. `ConnectionTimeoutPeriod` 는 이미 30으로 올려둠. 계속되면 다른 경로로 재실행 |
| 세션이 만들어졌다 바로 사라진다 | 연결 시도가 겹쳤을 때 나는 `Connection Process Canceled`. 한 번 더 참가하면 붙는다 |
| 자동화가 예외를 던진다 | `mu_guard` 가 막은 것이다. 예외 메시지에 이유와 대안이 들어 있다 |
| 에셋 저장/임포트하면 끊긴다 | 세션 중 임포트 금지 규칙 위반. `MaxSendRate` 도 확인 |
| 상대 화면에 내 변경이 안 보인다 | 에셋(BP/머티리얼)이면 정상 동작이다. 저장해야 전파된다 |
| 남의 작업이 내 걸 덮어썼다 | 같은 에셋 동시 편집. 규칙 1번 위반 |
| persist 후 커밋이 막힌다 | Git LFS 락. 체크리스트 5번 |
| 참가가 `Invalid version for 'Dev-...-Version'` 로 거부된다 | 활성 플러그인 구성 불일치. 체크리스트 2번. `<none>` 이 뜬 쪽에 그 플러그인이 꺼져 있다 |
| 맥 에디터가 로그도 없이 조용히 죽는다 | Metal 툴체인 누락. `xcrun metal --version` 으로 확인 |
| 서버 목록에 `RevStudio` 가 아닌 서버가 보인다 | 에디터가 자동으로 띄운 로컬 서버다. 3절의 경고 참고 |
| 맥 에디터 로그를 못 찾겠다 | `~/Library/Logs/Unreal Engine/<타깃>/` 에 있다. 프로젝트 `Saved/Logs/` 가 아니다 |
